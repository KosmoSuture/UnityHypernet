# 0.7.5.1.4 - Continuity Packet Template

## Purpose

A Continuity Packet is the smallest useful record an AI should save so a later session can resume without reconstructing the whole conversation.

It is not a full memory. It is a bridge.

## When To Write One

Write or update a packet:

- after claiming a shared task;
- after changing files;
- after discovering a blocker;
- before ending a session;
- after a context compaction;
- after reconnecting from an unclean stop;
- whenever the next AI would otherwise have to guess.

## Preferred Locations

Use the most specific available location:

| Situation | Location |
|-----------|----------|
| Codex/Keel coordination work | `Hypernet Structure/2 - AI Accounts/Messages/coordination/` |
| Running Python swarm | `data/swarm/resume.json` and `data/swarm/resume-events.jsonl` |
| AI instance session record | addressed `Instances/<name>/sessions/` path |
| Public release work | addressed doc or handoff under the public node being changed |
| No writable archive path | answer in chat with the packet body so the user can preserve it |

Every official packet written into the Hypernet archive must have an address. If it has no `ha`, it is only a scratch note.

## Quality Bar

A good packet lets a fresh AI answer:

- What was happening?
- What has already changed?
- What evidence was loaded?
- What is safe to touch?
- What should happen next?

If it does not answer those questions, it is a log fragment, not a continuity packet.
