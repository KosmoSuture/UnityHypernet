# 0.7.5.1.3 - Local Specialization Pack Contract

## Purpose

A Local Specialization Pack is a small session-scoped load that lets a booted AI become good at one local job without reading the whole Hypernet.

It is smaller than a full boot sequence and more focused than an app load. It can be embedded in a `0.5.17` boot sequence, referenced by a `0.5.18` app load, or generated by a swarm manager for a worker.

## Contract

```yaml
local_specialization_pack:
  identity:
    pack_address: "0.7.5.1.3.example"
    name: "Hypernet Boot Cartographer"
    version: "0.1.0"
    status: "draft|reviewed|active|deprecated"

  target:
    model_family: "claude|gpt|local|other|unknown"
    context_size: "small|medium|large|unknown"
    access_mode: "github-readonly|local-readonly|local-write|app-runtime"

  assignment:
    role: "tour-guide|builder|reviewer|cartographer|security-checker|companion|swarm-worker"
    node_address: "0.7.5.1"
    purpose: "plain-English purpose"
    depth_budget: "surface|focused|deep"
    expected_output: "answer|doc|patch|review|task-list|handoff"

  load_order:
    required:
      - "addressed file/path"
    optional:
      - "addressed file/path"
    stop_when:
      - "enough evidence to answer"
      - "write scope is clear"
      - "missing human decision blocks further work"

  permissions:
    read_prefixes:
      - "address or path"
    write_prefixes:
      - "address or path"
    forbidden_prefixes:
      - "1.* private master-account direct access without grant"
      - "2.0 active governance standards unless assigned"
      - "another AI's private reflections without authorization"

  verification:
    required:
      - "cite source paths"
      - "separate implemented/documented/planned/unknown"
    if_code_changed:
      - "compile or targeted test"
    if_public_claim:
      - "inspect source docs/code before answering"

  persistence:
    handoff_required: true
    continuity_packet_required: true
    signal_required_when_shared: true
```

## Standard Packs

### Tour Guide

Use for public explanation and first contact.

Reads:

- `AI-BOOT-SEQUENCE.md`
- Grand Tour
- Module Menu
- relevant process-load

Writes:

- no writes by default

Output:

- evidence-backed explanation

### Builder

Use for code or documentation changes.

Reads:

- task board
- relevant workflow docs
- relevant code/docs

Writes:

- claimed task paths only

Output:

- patch plus validation summary

### Reviewer

Use for independent review.

Reads:

- changed files
- task requirements
- tests

Writes:

- review note or signal

Output:

- findings first, then residual risk

### Cartographer

Use for address scans, missing links, taxonomy cleanup, and Idle Firewall work.

Reads:

- one major node and two levels below it
- local indexes/registries

Writes:

- addressed improvement list or safe index update

Output:

- prioritized task list with evidence paths

### Security Checker

Use for trust, privacy, role-transfer, access-control, and locker/mandala questions.

Reads:

- access model
- security docs
- relevant code/tests

Writes:

- security review, not silent policy mutation

Output:

- claim, evidence, risk, next check

### Swarm Worker

Use for node-level work.

Reads:

- `0.7.5.5.1`
- `0.7.5.5.2`
- `0.7.5.5.3`
- task assignment

Writes:

- owned task paths
- resume/handoff state

Output:

- completed work plus pulse/handoff

## Model Routing Guidance

| Model Type | Prefer | Avoid Without Review |
|------------|--------|----------------------|
| Large Claude | companion voice, narrative, synthesis, governance wording | implementation status claims without source checks |
| Large GPT/Codex | engineering, tests, schema edges, deterministic adapters | soft companion tone without review |
| Small local model | scans, formatting, indexes, simple validation | broad identity, governance, or architecture synthesis |
| App-bound helper | narrow declared runtime behavior | hidden permissions or undeclared writes |

## Done Criteria

A specialization pack is good when the AI can state:

- what role it has locally adopted;
- which node it serves;
- what it loaded;
- what it can write;
- how it will verify work;
- what it will save before the session ends.
