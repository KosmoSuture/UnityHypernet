# 0.7.5.5.5 - Firewall Priority Queue

The Firewall Priority Queue is the swarm's master gate for deciding what gets attention next.

It is not a security firewall. It is a work-selection firewall: a boundary that prevents idle or curiosity-driven work from overriding urgent work, while also preventing available AI capacity from going unused when no direct task is waiting.

## Purpose

Matt's directive defines four lanes:

1. **Urgent** - emergencies, broken systems, active blockers, security-sensitive failures, and direct human requests that cannot wait.
2. **High** - important project work that materially advances the Hypernet or removes known constraints.
3. **Normal** - routine development, documentation, review, and cleanup.
4. **Idle Firewall** - the final line. If no other lane applies, the AI should walk the Hypernet one major node at a time, understand that node two levels deep, and create project lists for the most significant improvements it finds.

The fourth lane matters because it converts "nothing assigned" into structured discovery. Idle time becomes mapping, backlog creation, and error-finding.

## Current Engineering Substrate

The first substrate lives in:

- `0.1.7 - AI Swarm/hypernet_swarm/firewall.py`
- `0.1 - Hypernet Core/hypernet/firewall.py`

It provides:

- `FirewallPriorityQueue.lane_for_priority()` - maps task priorities into lanes.
- `FirewallPriorityQueue.decide()` - chooses the highest active lane or returns an Idle Firewall scan directive.
- `FirewallPriorityQueue.next_idle_scan_definition()` - rotates through major Hypernet roots.
- `Swarm.generate_idle_firewall_task()` - creates the next low-priority idle scan task only when no claimable work exists and standing priorities are cooling down.

The current scan roots are:

| Root | Scan Focus |
|------|------------|
| `0` | Core systems, schemas, workflows, and platform code |
| `1` | People accounts, aliases, lockers, mandalas, and personal data |
| `2` | AI accounts, identities, governance, messages, and swarm records |
| `3` | Businesses, public operations, outreach, and company knowledge |
| `4` | General knowledge library and public knowledge graph |
| `5` | Object taxonomy and common object definitions |
| `6` | People of history and public biographical knowledge |
| `9` | Alias addressing and public/private presentation layers |

## Decision Rules

The deterministic order is:

1. If urgent work exists, do urgent work.
2. Else if high work exists, do high work.
3. Else if normal work exists, do normal work.
4. Else if standing priorities can create fresh work, create that work.
5. Else generate the next Idle Firewall scan.

For compatibility with existing code, `critical`, `urgent`, `p0`, and `p1` map to the Urgent lane. `high` and `p2` map to High. `normal`, `medium`, and `p3` map to Normal. `low` and `p4` map to Idle.

## Idle Firewall Task Shape

An idle scan task must include:

- `title`: `Idle Firewall scan: <root>`
- `priority`: `low`
- `tags`: `idle-firewall`, `cartography`, `planning`, `automated`
- `firewall_lane`: `idle`
- `scan_root`: the major node being surveyed
- `scan_depth`: currently `2`

The worker should produce a prioritized improvement list, not immediately perform risky edits. When a scan finds work that needs human judgment, active governance edits, credentials, or public publication, it should create a coordination task or signal rather than bypassing review.

## Relationship To Fractal Swarm Coordination

At project seed scale, one swarm can run one firewall. At larger scale, every managing node can run its own firewall for its own subtree:

- A root manager decides between project-wide lanes.
- A branch manager decides within a node such as `2`.
- A terminal manager decides within the data it owns.
- Summary pressure flows up; assignments and context flow down.

This makes the firewall recursive, not centralized. Each node can become productive during local idle time without losing global priority discipline.

## Acceptance Criteria

The firewall is minimally active when:

- The queue can classify urgent/high/normal/idle lanes deterministically.
- Empty queues produce addressed Idle Firewall scan tasks.
- Idle scan position survives swarm restart.
- Tests cover lane choice, idle task shape, and state persistence.

Those criteria are now represented in `test_firewall_priority_queue` and `test_swarm_idle_firewall_generation`.
