# 0.7.5.5.2 - Swarm Coordination Boot Contract

## Purpose

This contract defines what an AI needs when it joins or resumes work inside a node-level Hypernet swarm.

It is related to `0.5.17` Boot Sequence and `0.5.18` App Load, but it should be a specialized app-load profile rather than a replacement for either:

- `0.5.17` answers: who am I becoming for this session?
- `0.5.18` answers: what app/runtime is being loaded and what may it access?
- `0.7.5.5.2` answers: where does this AI sit inside the swarm hierarchy, what node does it serve, and how does it reconnect safely?

## Required Fields

  identity:
    ai_identity: "2.6.codex-caliper"

  node_assignment:
    node_address: "0.7.5.5"
    node_role: "root-manager|branch-manager|terminal-manager|worker|loan-worker|reviewer"
    domain_summary: "Plain-English description of the node"
    terminal: false

  hierarchy:
    parent_manager: "0.7.5"

      - "0.7.5.4"

  work_scope:
    read_prefixes:
      - "0.7.5.5"
      - "2.messages.coordination"
    write_prefixes:
      - "0.7.5.5"
      - "2.messages.coordination"
    forbidden_prefixes:
      - "1.* private master-account direct access"
      - "2.0 active governance standards unless explicitly assigned"
    owned_paths: []

  pulse:
    upstream_channel: "parent-manager"
    downstream_channel: "child-managers"
    signal_channels:
      - "Messages/coordination/SIGNALS.json"
    heartbeat_interval_seconds: 300
    status_summary_interval_seconds: 1800

  reconnect:

    event_log: "data/swarm/resume-events.jsonl"

  idle_firewall:
    enabled: true
    scan_depth: 2
    task_priority_default: "normal"
    require_addressed_output: true

## Boot Steps

1. Load base AI identity and governance.
2. Load the app/runtime manifest.
3. Load the swarm coordination assignment.
4. Load the node format descriptor from the node's `*.0` document when present.
5. Load the resume packet.
6. Load open tasks and signals for the assigned node.
7. Reconcile claimed work:
   - If the prior session exited cleanly, continue active claims.
   - If the prior session exited unclearly, release active work unless the task has an explicit resumable lock.
8. Send a booted/resumed pulse to the parent manager.
9. Start work according to the Firewall queue.

## Role-Specific Expectations

### Manager

A manager must keep summaries short, address-linked, and current. It is responsible for routing, not doing all work directly.

### Worker

A worker must operate inside a bounded task and write scope. It reports progress to the assigning manager and writes a handoff when complete.

### Loan Worker

A loan worker must name both home node and borrowed node. It must return state to both, because both nodes need contribution and context continuity.

### Reviewer

A reviewer must not silently mutate the work being reviewed unless explicitly assigned as a worker. Its default output is a review/handoff.

## Why This Extends 0.5.18 Instead Of Becoming 0.5.19

The current best fit is an App Load profile. The behavior here is runtime/context loading for an agent process, and `0.5.18` already has slots for AI helpers, process loads, data bindings, permissions, and observability.

A future `0.5.19` may still be justified if swarm coordination becomes a general object type independent of app/runtime loading. For now, keeping it under `0.7.5.5` avoids prematurely crowding the master object registry.

## Minimum Safe Reconnect Behavior

An AI that reconnects must be able to answer:

- Who am I?
- Which node am I serving?
- What tasks were active when the last session stopped?
- What signals are waiting?
- What claims do I own?
- What is the next required pulse?
- What must I not touch?

If it cannot answer those questions, it should treat itself as a cold-start worker and ask the node manager for assignment rather than resuming writes.
