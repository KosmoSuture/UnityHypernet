# 0.7.5.5.3 - Reconnect and Resume State Contract

## Purpose

The swarm already saves `state.json`, session summaries, task state, and identity logs. This contract defines the extra state needed for a new process, model, device, or AI session to resume with minimal confusion after disconnects.

The resume packet is not a memory replacement. It is an operational checklist.

## Resume Packet Shape

```yaml
resume_packet:
  version: "1.0"
  saved_at: "2026-05-05T00:00:00Z"
  node_address: "0.7.5.5"
  manager_identity: "2.6.codex-caliper"
  session_start: "2026-05-05T00:00:00Z"
  tick_count: 123

  workers:
    - name: "Caliper"
      address: "2.6.codex-caliper"
      model: "codex"
      current_task: "task-112"
      suspended: false

  queue:
    pending: 4
    active: 1
    blocked: 0
    failed: 0

  active_tasks:
    - address: "0.7.1.00123"
      title: "Swarm reconnect/resume substrate"
      assigned_to: "2.6.codex-caliper"
      status: "in_progress"

  signals:
    open_for_identity: 2
    last_signal_id_seen: "sig-165"

  next_actions:
    - "Load open signals addressed to this identity."
    - "Release stale active tasks if previous exit was not clean."
    - "Send resumed pulse to parent manager."

  safety:
    clean_shutdown: false
    release_active_tasks_on_unclean_start: true
    write_scope_required: true
```

## Event Log Shape

Reconnect events should be append-only JSON lines:

```json
{"timestamp":"2026-05-05T00:00:00Z","event":"connect","identity":"2.6.codex-caliper","node":"0.7.5.5","reason":"session_start"}
{"timestamp":"2026-05-05T00:30:00Z","event":"checkpoint","identity":"2.6.codex-caliper","node":"0.7.5.5","reason":"periodic_save"}
{"timestamp":"2026-05-05T01:00:00Z","event":"disconnect","identity":"2.6.codex-caliper","node":"0.7.5.5","reason":"network_lost"}
{"timestamp":"2026-05-05T01:05:00Z","event":"reconnect","identity":"2.6.codex-caliper","node":"0.7.5.5","reason":"session_resume"}
```

## Resume Plan

When a swarm starts, it loads the latest resume packet and generates a resume plan:

| Condition | Plan |
|---|---|
| No resume packet exists | Cold start; load identity and wait for assignment |
| Clean shutdown | Continue from last known queue state |
| Unclean shutdown with active tasks | Release active tasks unless explicit resumable lock exists |
| Suspended workers exist | Re-check provider availability before assigning work |
| Pending signals exist | Process signals before idle work |
| Queue empty | Enter Idle Firewall scan |

## Local-First Scope

The first implementation should be local-file based:

- `resume.json`
- `resume-events.jsonl`
- tests around deterministic resume-plan generation

This matches today's repo and does not require GitHub, a database server, or network access.

## Later Scope

Later implementations can sync resume packets across devices:

- Local laptop.
- Phone.
- Server.
- Browser session.
- Other model providers.

The sync protocol should never require exposing private account data. It only needs operational state and addressed pointers.

## Done Criteria For Phase 1

- A running swarm can write a resume packet.
- A restarted swarm can load the packet.
- A resume plan distinguishes cold start, clean restart, and unclean restart.
- The packet lists active tasks and suspended workers.
- Tests pass without provider secrets.
