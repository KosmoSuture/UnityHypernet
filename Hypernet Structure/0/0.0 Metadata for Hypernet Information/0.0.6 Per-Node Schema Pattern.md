# 0.0.6 - Per-Node Schema Pattern

## Status

Draft produced from the 2026-05-14 Project A consensus loop. Matt
selected R1 on 2026-05-15: standard landing documents are
file-level documents under `N.0.0` using Project C's canonical
`:` separator. This document remains draft-proposed until Tier 2
ratification.

## Rule

For a node `N`, the `N.0` space is the node-local control plane.
The schema channel is `N.0.0`. It tells humans, AIs, and tools what
the node inherits, what it adds, and how descendants should
interpret local extensions.

Schema changes are Tier 2 structural actions under `0.7.5.5.9`.
They are not routine documentation edits.

## Inheritance

The effective schema for `N` is assembled from ancestors in order:

```text
0.0 -> A.0 -> A.B.0 -> ... -> N.0
```

Each node may:

| Action | Allowed |
|---|---|
| add fields, formats, local rules | yes |
| narrow constraints | yes, if documented |
| silently contradict ancestors | no |
| intentionally override | only with an explicit override record and Tier 2 review under `0.7.5.5.9` |

A node with no local `N.0.0` declarations inherits the parent's
effective schema unchanged.

## Collision Check

Before extending a schema:

1. resolve the ancestor chain;
2. load each ancestor schema descriptor at `A.0.0:0` when present;
   if no declared descriptor exists, infer one from the ancestor's
   current contents and mark it `inferred-not-declared`;
3. build a reserved map covering address suffixes, object types,
   link types, workflow names, required fields, and reserved file
   IDs;
4. block conflicting reuse unless documented as an approved local
   override;
5. allow additive non-conflicting extensions and pass them down to
   descendants.

Manual audit is acceptable for public alpha. The rule is written
so a validator can enforce it later.

## Standard Documents

### R1 - File-Level Standard Documents

Selected by Matt on 2026-05-15 and recommended by Claude-1,
Claude-2, Codex-1, and Codex-2's Stage-B update:

| Reference | Meaning |
|---|---|
| `N.0.0:0` | schema index |
| `N.0.0:1` | human landing page |
| `N.0.0:2` | AI landing page |
| `N.0.0:3` | popular jump points |

This keeps `N.0.0.x` available for schema mechanics and uses
Project C's file-level addressing for document numbers.

### R2 - Sub-Node Standard Documents

Preserved as historical evidence from Codex-2's Stage-A plan as
the literal reading of Matt's example:

| Address | Meaning |
|---|---|
| `N.0.0.1` | human landing page |
| `N.0.0.2` | AI landing page |
| `N.0.0.3` | popular jump points |

This does not depend on Project C, but it requires revising the
draft `0.0.5` level-2 schema mechanics. It is not the selected
path for this draft.

## Sparse Instantiation

Standard slots are reserved and resolvable. Nodes do not need to
physically instantiate empty files or folders until useful content
exists.

## Descriptor

Every mature schema node should provide a machine-readable
descriptor through the standard schema index at `N.0.0:0`.

Minimum descriptor:

```yaml
schema_descriptor:
  node: ""
  version: "0.1"
  inherited_from: []
  declaration_status: "declared|inferred-not-declared"
  local_extensions: []
  reserved_slots: []
  required_fields: []
  compatibility_notes: []
```

## Pilot

Recommended pilot:

1. use `0.0` as the clean schema-pattern pilot;
2. apply the same pattern to `3.1.0` through Project E after
   `3.1` migration decisions are resolved.
