# 0.0.7 - File-Level Addressing

## Status

Draft produced from the 2026-05-14 Project C loop. Matt selected
`:` as the canonical file-level separator on 2026-05-15,
overriding the AI recommendation for `#`. This document remains
draft-proposed until Tier 2 ratification.

## Purpose

Node addresses identify folders/nodes. File-level references
identify a document inside one node without making the document ID
globally meaningful.

```text
HML://0.3     -> node 0.3
HML://0.3:2  -> file 2 inside node 0.3
```

## Canonical Separator

Use `:`.

Matt selected `:` for Hypernet readability. In an HML reference,
the colon after the address is a Hypernet file selector, not a URI
scheme separator, port separator, or Windows path marker.

Parser rules:

| Rule | Requirement |
|---|---|
| address parse | parse `HML://` scheme first, then Hypernet address, then optional version, then optional file selector |
| file selector | the rightmost `:` after the address/version boundary selects a file |
| filesystem safety | file references are logical; do not infer Windows drive paths from them |
| import compatibility | `#` is not an alias in v1; migration tools may rewrite old draft references to `:` with provenance |

## Grammar

```text
ADDRESS_REF ::= ADDRESS [VERSION] [FILE]
VERSION     ::= "@" ("latest" | "v" DIGITS)
FILE        ::= ":" FILE_ID
FILE_ID     ::= DIGITS | NAMED_ID
NAMED_ID    ::= LOWER (LOWER | DIGIT | "-")*
```

Examples:

| Ref | Meaning |
|---|---|
| `0.3` | current node `0.3` |
| `0.3:2` | file 2 in current node `0.3` |
| `0.3@v4:2` | file 2 in version 4 of node `0.3` |
| `HML://0.3@latest:2` | file 2 in latest node `0.3` |
| `0.3:project-index` | named file ID in current node `0.3` |

Invalid:

```text
0.3:
0.3::2
0.3:2@v4
0.3:2_bad
```

Version comes before file selection because the version chooses the
node snapshot whose file index is then consulted.

## Data Model

Do not widen `HypernetAddress` itself. Use a reference wrapper:

```python
HypernetReference(
    address=HypernetAddress("0.3"),
    version="v4",
    file_id="2",
)
```

## Allocation

| Rule | Requirement |
|---|---|
| scope | file IDs are unique within one node |
| reuse | retired public IDs are not reused |
| storage | file frontmatter plus node file index |
| move | old public ref receives redirect/provenance |
| identity | `N:id` is a locator, not the object's global identity |

### ID Forms

| ID form | Rule |
|---|---|
| `:0`-`:9` | reserved standard band, numeric only |
| `:10+` | ordinary node-local documents, numeric preferred for ordered dense lists |
| named IDs | allowed for stable semantic references; lowercase hyphen-separated; must start with a letter |

### Reserved Standard Band

File IDs `:0` through `:9` are reserved for standard documents
coordinated with the per-node schema pattern (`0.0.6`). Matt
selected the R1 option on 2026-05-15:

| Reference | Meaning |
|---|---|
| `N.0.0:0` | schema index |
| `N.0.0:1` | human landing page |
| `N.0.0:2` | AI landing page |
| `N.0.0:3` | popular jump points |
| `N.0.0:4`-`N.0.0:9` | reserved for future universal standard documents |

Node-local public documents start at `:10` unless a node schema
explicitly reserves additional local slots. Category-specific
standards should prefer named IDs above `:10` unless elevated to
the universal reserved band by Tier 2 review.

### Versioning Boundary

`0.3@v4:2` means file `2` in version `4` of node `0.3`.
Independent file-level version syntax is not part of v1. Reserve
`0.3:2@vK` for a future extension if file histories later need to
version independently from their node snapshot.

Frontmatter:

```yaml
ha: "0.3"
file_id: "2"
file_ref: "0.3:2"
```

Node file index:

The logical node file index lives in the standard schema index
document `N.0.0:0` under `files:`. A file-backed adapter may
materialize that index directly in the schema-index document or in
a file it names via `files_index_ref`; resolvers treat the indexed
data as authoritative.

```yaml
node: "0.3"
index_ref: "0.3.0.0:0"
files:
  "2":
    path: "example.md"
    title: "Example"
    ha: "0.3"
```

## Interaction With `*.0`

`N.0.0.1` is a node address. `N.0:1` is file 1 inside node `N.0`.
The namespaces do not collide because `.` and `:` are different
operators.
