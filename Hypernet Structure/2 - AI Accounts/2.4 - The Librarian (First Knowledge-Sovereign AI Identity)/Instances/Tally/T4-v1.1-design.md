## 1. Goals

- **G1 — Uniform vendor coverage (Matt's north star).** Claude (v1.0) and **Codex** call paths log
  **identical normalized fields**, with **identical enforcement** (HardStop/Pause before every
  call) and the **same chain**, in one ledger.
- **G2 — Multi-engine readiness (Matt Q2 "work with anything").** A future engine (Gemini, …) is
  one adapter + one cost model — **no core change** — including engines with non-token-count or
  non-two-rate billing.
- **G3 — Reconciler seam (`2.7.23` L1.5)** with defined correctness semantics (race, partial
  window, idempotency, malformed disclosures); live provider pulls may defer.
- **G4 — Durable rule placement** of the metered-or-disclosed rule (`2.7.23` + spawn-packet
  protocol).
- **G5 — Structured, parseable `codex-unmetered` disclosures.**
- **G6 — S.3 hardened-chain seam (mandatory)** that is **primitive-agnostic** (opaque proof), so
  HMAC / anchor / signer-separation drop in with no ledger rework; the unkeyed chain is not
  entrenched.
- **G7 — Backwards compatibility (new, Codex #6):** the exact v1.0 public APIs + the 22-test
  harness keep working unchanged.

## 2. Non-goals

- `2.7.23` forecaster (L2), swarm pause (L3), resume (L4), dashboard (L5).
- The hardened-chain **implementation** is the §5a decision; the **seam** is in scope regardless.
- Live provider-billing API integration (seam yes; pulls may defer).
- Deployment, Codex bot/credential setup.

## 4. Architecture / approach

v1.0's **enforcement core** is unchanged (Codex #6 confirmed it: enforce-before-call + append-after
at `wrapper.py:340-361`; 22/22). v1.1 adds layers **above/beside** it and one **seam inside** the
ledger — all backward-compatible.

```
   engines │ ClaudeAdapter   CodexAdapter   <GeminiAdapter> ...
           │   to_normalized_usage(raw) -> NormalizedUsage          (R1,R2,R3)
           ▼
   cost    │ CostModel.estimate(usage, model, context) -> CostEstimate   (R2, non-tuple)
           ▼
   core    │ TokenAccountingWrapper.call() ── enforce(HardStop/Pause) ── record()   (UNCHANGED; R7)
           ▼
   ledger  │ TokenLedger.record(row)
           │   chain_link = self._chain.link(prev_state, row)   ◄── S.3 SEAM, opaque (R6)
           │      UnkeyedHashChain | HmacChain | AnchoredChain | SignerChain
           │   + reconciled_usage table (defined semantics)     ◄── R3
           │   + disclosures table (structured + malformed)     ◄── R5
```

### R1/R2 — engine adapters + cost models (Codex #3)
- **`EngineAdapter`** protocol: `engine_id: str`, `to_normalized_usage(raw_response) ->
  NormalizedUsage`. A registry maps `engine_id → adapter`.
- **`NormalizedUsage`** preserves common fields **when available** — `input_tokens`,
  `output_tokens` — **plus** `usage_dimensions_json` (prompt/candidate/cached/reasoning/media/tool
  dimensions for engines like Gemini), `raw_usage_json` (provider response verbatim),
  `estimation_source` (`provider-response` | `externally-estimated` | `disclosed`), and
  `provider`/`request_id` for reconciliation. (Some engines don't return counts synchronously —
  `estimation_source` records that.)
- **`CostModel`** protocol replaces the two-rate tuple: `estimate(usage: NormalizedUsage, model:
  str, context: PricingContext) -> CostEstimate`. `PricingContext` carries region, batch/realtime,
  cache read/write, per-request fees, billing-window adjustments. The default **`TokenCostModel`**
  reproduces v1.0's input/output per-1k math; a `GeminiCostModel` can price per-modality /
  per-image-unit. Cost is no longer assumed to be a function of just two token counts.
- **ClaudeAdapter** normalizes Anthropic `usage`; **CodexAdapter** parses `codex exec --json`
  per-call usage events — both into `NormalizedUsage`, both priced by a `CostModel`, both into one
  ledger with identical schema + enforcement.

### R3 — reconciler seam with semantics (Codex #4)
`reconciled_usage` is append-only and **re-runnable (idempotent)**, with fields:
`window_start, window_end, coverage_start, coverage_end, coverage_status ∈ {partial, final},
provider_cursor|run_id, ledger_row_range, disclosure_ids, malformed_disclosure_ids,
billed_units_json, billed_cost_usd, delta_json, source, created_at, idempotency_key`.
Semantics: **race** — a snapshot/ingestion watermark fixes which ledger rows + disclosures a run
covers, and a run is keyed by `idempotency_key` so re-runs don't double-count; **partial window** —
provider results stay `coverage_status=partial` until the billing window is settled, never mistaken
for `final` truth; **malformed disclosures** — recorded in `malformed_disclosure_ids` as **invalid
evidence with an audit path**, never silently dropped. Live provider pulls may defer; the table +
interface + semantics ship.

### R5 — structured disclosure (Vellum #5)
A `codex-unmetered` disclosure is a structured record ingestible into a `disclosures` table:
`{instance_name, account, role, engine, model, reason_code ∈ {one-shot, brief-task,
wrapper-unavailable, other}, timestamp_utc, disclosed_by, billing_reconstruct_pointer (provider +
time-window + request-id-range)}`, emitted as coordination frontmatter (`flags:[codex-unmetered]` +
an `unmetered_disclosure:` block). Malformed → rejected as a valid exception **and** logged as
malformed evidence (feeds R3).

### R4 — durable rule placement (build-phase edits, named not made)
(a) new `2.7.23` section (metered-or-disclosed rule + v1.1 parity); (b) spawn-packet protocol field
— every packet's T.4 section declares `metering: wrapper` **or** `metering: codex-unmetered` + the
R5 disclosure. (My Spawn Packet 01's per-call-wrapper clause generalizes into the template.)

### R6 — S.3 seam, **opaque** (Codex #1)
Chain construction sits behind a `ChainPrimitive`:

```
link(prev_state, row) -> ChainLink(prev_state, new_state, proof, algorithm, authority_ref)
verify(rows) -> bool
anchor() -> AnchorRef | None
```

The link is an **opaque record**, not `(row_hash, new_state)` — so it generalizes beyond hashes:
for **signer-separation** the persisted `proof` is a signature + key id + signer id + signer's
monotonic state; `algorithm` and `authority_ref` name the primitive + its authority root. The
ledger persists generic `prev_state`, `chain_state`, `chain_proof_json`, `algorithm`,
`authority_ref`; v1.0's `sha256(prev+row)` becomes **`UnkeyedHashChain`** (writing its hash into
`chain_proof_json`, and into the legacy `row_hash`/`prev_hash` columns for R7 compat). **No ledger
code outside `UnkeyedHashChain` computes or recomputes a hash** — the ledger only calls
`self._chain.link()/verify()`. HMAC, anchor, and signer-separation drop in with zero ledger rework.

### R7 — backwards compatibility (Codex #6)
- Legacy `TokenAccountingWrapper(ledger, budget, instance_name, account, provider, model, …)`
  constructor, legacy `CallResult(input_tokens, output_tokens, request_id, payload)`, and the
  module-level `estimate_cost_usd(model, in, out)` function **remain valid** (the latter as a compat
  shim over `TokenCostModel`). A legacy `CallResult` maps to a `NormalizedUsage` with those two
  fields + `estimation_source=provider-response`.
- The new `engine` column **defaults** from adapter/provider/model for legacy callers — **not** a
  required positional arg, **not** a `NOT NULL` column without a default. New chain/reconciler
  columns are added with defaults; **migrations populate old rows**.
- **The exact current `python -m token_accounting.test_wrapper` harness (22 checks) must pass
  unchanged after the build.**

## 5. Alternatives (CM — Matt picks at the design-review gate)

### 5a. S.3 fold timing — ★ both options are SECURITY decisions (Codex #5 correction absorbed)
The seam is mandatory **either way**; the choice is *implement the hardened primitive now or next*.
**Crucially, Alt B is not a pure efficiency choice — it carries a bounded security exposure.**

- **Alt A — Fold S.3 into v1.1 (one pass).** Ships parity **and** a hardened `ChainPrimitive`.
  - *Pro:* metered **and** tamper-evident when v1.1 lands; no forgeable window; one red-team/build.
  - *Con:* bundles **key management** (§5b); gates Scribe-unblock on the key-storage decision.
- **Alt B — Meter now (S.3-ready), S.3 fast-follow into the seam.**
  - *Pro:* two smaller independently-verifiable changes; Scribe unblocks sooner; no double *design*
    rework (the seam guarantees it).
  - *★ Security cost (not just efficiency):* shipping `UnkeyedHashChain` in production opens a
    **window in which a dishonest or compromised local writer can recompute-forge the entire audit
    chain**, and the **founder-kill backstop does not preserve audit integrity for that window.**
  - **If Alt B is chosen, it REQUIRES all of:** (a) **explicit Matt risk-acceptance** of the
    forgeable-audit window; (b) a **committed maximum fast-follow interval** — *I propose 7 days*
    (short enough to bound the exposure on core audit infrastructure, achievable because the seam is
    already in place and the anchor primitive is small; Matt may tighten); (c) **explicit
    acknowledgment that any role unblocked before S.3 lands (e.g. Scribe/packet 02) operates with a
    recompute-forgeable audit ledger during the window.**

### 5b. Key-storage options — with **validity conditions** (Codex #2)
Each option is only secure under its stated condition; absent the condition, it does **not** defeat
the same-OS-user local-writer threat.

| Option | What | **Valid ONLY when** | Notes |
|---|---|---|---|
| **(i) File** (`~/.hypernet/audit-key`) | HMAC key in a file | **OS-account separation** or equivalent isolation from the metered process (no readable backup, no inherited admin/session creds) | under same-OS-user, **broken** |
| **(ii) Windows Credential Manager** | key in OS keystore | **OS-account separation** (a same-user process can retrieve that user's creds) | protects only other users / at-rest unless paired w/ `2.7.22` lockdown |
| **(iii) Anchor (no key)** | checkpoint head+count to a Matt-controlled file / external remote | the **anchor sink is outside the metered instance's write authority**, **enforces monotonic head/count**, and has **protected credentials or mandatory signature verification** | else a local attacker rewrites the chain *and* submits a new anchor |
| **(iv) Signer-separation** | a separate signer signs appends | **isolated signer key + signer-owned monotonic `(seq, head/state)` + protocol that signs ONLY the next append** (verifies `prev_state==last_state`, `seq==last_seq+1`, recomputes from canonical row), **not proposer-supplied histories** | else the proposer feeds a rewritten chain and separation collapses |

**My lean (offered, NOT decided — Matt's call):** **(iii) anchor** — no key-management failure
surface, matches the `2.7.22` git-checkpoint pattern + my verifiable-by-correspondence method, and
its validity conditions are achievable (external remote without instance push authority + monotonic
policy). (iv) signer-separation is the strongest end-state. **(i)/(ii) require the `2.7.22`
OS-account lockdown to be valid at all** under the local-writer threat — see §7 Q5.

## 6. Acceptance criteria + test plan

- **AC1 (R1):** a Claude call and a Codex call produce ledger rows with **identical schema**, both
  enforced before the call, both chained into one ledger.
- **AC2 (R2, Codex #3):** registering a **third dummy engine whose billing is NOT input/output
  token pricing** (e.g. per-image-unit / per-modality, or externally-estimated counts) logs
  correctly with **no core/ledger/chain change**, via `CostModel`/`NormalizedUsage`.
- **AC3 (enforcement parity):** HardStop (100%) / Pause (95%, non-personal) fire identically across
  engines; the refused call appends no row.
- **AC4 (R3, Codex #4):** `reconciled_usage` + `Reconciler` exist; a stub run is **idempotent**
  (re-run does not double-count), marks partial windows `partial`, and records malformed
  disclosures in `malformed_disclosure_ids` (not dropped).
- **AC5 (R5):** a well-formed disclosure parses into all fields; a malformed one is rejected **and**
  logged as malformed evidence.
- **AC6 (R6, Codex #1):** the ledger runs with `UnkeyedHashChain` and a **stub `SignerChain`
  returning a non-hash proof** through the **same `ChainLink` interface with no ledger code
  change**; `verify_chain()` delegates to the primitive; **a check asserts no ledger code outside
  `UnkeyedHashChain` calls `_row_hash` or recomputes a hash directly.**
- **AC7 (R7, Codex #6):** the **exact current `python -m token_accounting.test_wrapper` (22
  checks) passes unchanged**; legacy ctor / `CallResult` / `estimate_cost_usd` still import and
  work; `engine` defaults for legacy callers; a migration test populates old rows.
- **AC8 (Alt A only):** the chosen hardened primitive detects tamper per its stated guarantee
  (HMAC: forge-without-key fails; Anchor: rewrite past an anchored head detected; Signer: a
  proposer-supplied historical rewrite is refused).

**Test plan:** extend `test_wrapper.py` (keep the 22 unchanged) with mixed-engine parity (fake
Claude + Codex + a non-tuple-priced dummy engine), enforcement parity, reconciler idempotency +
partial + malformed, disclosure parse/reject, chain-primitive swap (unkeyed ↔ non-hash signer stub,
same API) + the no-direct-hash check, and a legacy-compat/migration suite. Codex attack-based
cross-model verification per Touchstone's standing requirement.
