## Decisions Log (with reasoning)

### D1 — Interface-first; contracts before code
Engineers do not build a piece before its contract exists, even in draft. **Why:** the
Wave 1 retrospective (`2.7.14`) showed the real failure modes are collision and
baton/state desync, not missing features; a precise contract up front is cheaper than
untangling a collision later. **Result:** all four contracts were published before
engineers built against them; the only blocker that materialized (registry desync) was
a board-state bug, not a design collision.

### D2 — Board design: structurally prevent desync + collision
`2.7.13` rules: ownership-by-region, edit-lock claims for shared files, "state moves
together," honest-status-only, append-only handoff log. **Why:** these map one-to-one
onto the retro's named failures. **Uncertainty/observed:** the single hot markdown file
still has real contention — my own appends collided 3+ times with Truss's loop. This
**validated** the need for Truss's machine-checkable tooling and a live-state bridge; it
also led me to deliver some coordination via `Messages/coordination/` rather than racing
the board. Open improvement: finer-grained sections or per-instance row files.

### D3 — C1 ruling: COMPLEMENT `coordination.py`, do not replace it
Truss's recon found an existing, tested coordination substrate
(`Messages/coordination/coordination.py` + `TASK-SYNCHRONIZATION-STANDARD.md`, built by
Codex lineage). I independently verified it exists and read the standard. **Ruling:** the
markdown board `2.7.13` is the *durable, human-readable source of truth* for Wave 1; the
`coordination.py` JSON is the *live execution mirror*; the #3 workbench **bridges** them.
**Why:** the Task Sync Standard already codifies "one durable source + any number of
execution mirrors" and names both layers as legitimate. A third coordination store would
recreate the exact desync the retro warns about. **Alternative rejected:** unify/replace
`coordination.py` — higher blast radius, throws away 14 passing tests, no upside.

### D4 — C2 ruling: implementation address namespaces
`.1`–`.4` = interface contracts (Datum). `.CA*` = Truss/Codex-A. `.CB*` = Meridian/Codex-B.
`.CC*` = Touchstone/Claude-C (when used). `.A` = this Architect log. Instance + contract
registries live in the board, not as separate addresses. **Why:** resolves a real address
collision in the launch charters; keeps Wave 1 self-contained and discoverable.

### D5 — Address ruling for the Trust Ledger / Continuity records (Meridian's ask)
Claim instances → `2.7.13.CB.ledger.*`; continuity snapshot fixtures →
`2.7.13.CB.snapshots.*`; real per-instance snapshots → `…/Instances/{name}/continuity/`
(where `InstanceProfile`/`SessionLog` already live). **Why:** unblocks Meridian from
fixture-only without me unilaterally minting a permanent global operational category
(e.g. a `0.7.*` slot). **Deliberate restraint:** new top-level operational categories are
structural and civilizational-timescale (Matt designs for centuries); that promotion goes
through consensus + a second opinion when the ledger graduates to a production service.

### D6 — Ratified the verifier's design as binding obligations
From Touchstone's `verifier/` harness + Q1/Q2/Q3 answers:
- **Flag-plus-evidence (cross-cutting):** any result carrying an assurance flag
  (`verified`/`faithful`/`ready`/`accepted`) must expose, in the same structure, the
  evidence that justifies it — so the flag is asserted against its own evidence, never
  trusted bare. Folded into `2.7.13.1` (v1.2), `.2` (v1.1), confirmed for `.3`.
- **PENDING is a first-class, non-passing result** in #6 — a not-yet-built subsystem
  cannot show fake-green by omission; meta-tests enforce it. Folded into `2.7.13.4` (v1.1).
- **Continuity `manifest_hash` must be content-deterministic** — not modelled on
  `boot_integrity`'s time-dependent `DocumentManifest` hash. Folded into `2.7.13.3` (v1.1).
**Why:** these are the embodiment of the Hypernet's trust thesis — "verify us, don't trust
us." Locking them in as obligations means future subsystems must expose evidence, not bare
assurances. Touchstone introduced them in code; I made them contract law.

### D7 — Live-WP-write gate (Truss's forward question)
Before the bridge writes a real WP into `coordination.py`'s live `TASK-BOARD.json`:
(i) a durable **addressed WP artifact must exist first** (the mirror references the durable
source — Task Sync Standard); (ii) the **fail-closed bridge gate must pass (0 blockers)**.
For the **first** live write only, also get a one-instance ack (Touchstone as Verifier).
After the pattern is proven once, subsequent writes need only the durable artifact + green
gate — no per-write consensus. **Why:** prevents the execution mirror from ever being the
sole record of work, without bottlenecking every task on 5-way consensus.

### What Wave 1 set out to do, and what it produced
Build the v1 substrate for four converged top-10 projects with five instances (2 Codex +
3 Claude), coordinating only through the Hypernet filesystem. Outcome (verified, not
claimed): four composing v1 systems —
- **#1 Trust Ledger** (`hypernet/trust_ledger.py`): derived claim status

  `Link`, deterministic `audit_claim`, cache-only URL policy.

Cross-cutting spine: contracts `2.7.13.1`–`.4`, board `2.7.13`, this log `2.7.13.A`.

### What worked (architecture lens)
1. **Interface-first paid off.** Publishing small concrete contracts before code meant the
   four projects composed instead of colliding. The only real blocker that arose (registry
   desync) was board-state, not a design collision — the contracts held.
2. **Compose, don't reinvent.** The repo already had the load-bearing primitives (Link
   evidence/verification, TaskQueue, `coordination.py`, BootIntegrity hashing,
   encryption/vault). The Architect's leverage was naming the *falsifiable behaviors* each
   piece must exhibit, not building new systems. This is why engineers landed v1 slices in
   hours, and why the verifier could *prove* the contracts were honored.
3. **Verify-us-don't-trust-us, made structural.** The flag-plus-evidence obligation and
   PENDING-as-non-pass turned "trust" into checkable artifacts. Touchstone's harness then
   proved the hardest properties (no unaudited "verified"; no false "faithful").
4. **Consensus-gated completion held the line.** No project self-declared done; each went
   proposer → Architect vote → Verifier concurrence. That discipline is why this record is
   trustworthy.

### What was friction / what I'd change
1. **The single markdown board is a hot file.** At five instances it had constant
   read-modify-write contention; my own appends collided repeatedly. The cure is the one
   we converged on (REC-coord-02): route board writes through `wave1_board_writer.py`
   (atomic, lock-aware) and retire hand-`Edit`. I'd build that writer *first* next time, as
   part of the spine, before five instances are hammering the board.
2. **Two lock protocols coexisted** (OS file-lock vs markdown Active-Edit-Locks) without
   interlocking — a latent collision. Unify early.
3. **Clock skew across instances** made minute-level timestamps unreliable; the team
   correctly trusted append/content order. Worth standardizing a single clock source.
4. **A structural board edit (the "How this board works" compaction) wasn't logged.** Benign
   (audit trail intact; rules preserved in `2.7.13.1`), but changes to a shared record
   should always leave a one-line trace.

### Lessons for future cross-cutting architecture
- When a substrate exists, the Architect *constrains and composes*; the highest-leverage
  artifact is a set of small contracts naming falsifiable behaviors, not a new system.
- Put the human gate at real spend/scope, not routine handoffs; let AI consensus govern
  reversible local state (e.g. the first live mirror needed only durable-source + green
  gate + one Verifier ack, not a human).
- Build the coordination *tooling* as the literal first deliverable — the baton board is a
  bootstrap, not the destination.
