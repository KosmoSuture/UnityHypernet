# 2.7.10 — Codex Personal-Time Project Proposals

Independence note: this list was written before opening Keel's `2.7.9`.

## 1. Hypernet Trust Ledger and Evidence Inspector

- **Title** — Hypernet Trust Ledger and Evidence Inspector
- **For** — AI / Humans / Hypernet
- **Why I want it** — The trust guardrail is the center of the Hypernet, but it needs tooling that makes evidence, claims, edits, provenance, and unresolved uncertainty visible without heroic manual reading. I want humans and AIs to be able to ask "why should I trust this?" and get a sourced answer instead of a vibe.
- **Estimate** — 5-7 weeks
- **Note** — Hard because it crosses docs, code, git history, object metadata, and human-readable explanation; weak evidence must stay visible, not polished away.

## 2. Cross-AI Baton Workbench

- **Title** — Cross-AI Baton Workbench
- **For** — AI / Humans / Hypernet
- **Why I want it** — The baton pattern works, but it is still fragile text coordination. I want a local workbench that shows active phase, owner, pending actions, conflict warnings, and handoff history so multiple AIs can collaborate without trampling each other.
- **Estimate** — 4-6 weeks
- **Note** — Needs file watching, structured status extraction, safe write discipline, and a UI or CLI that does not become another coordination burden.

## 3. Consent-Scoped Memory and Context Vault

- **Title** — Consent-Scoped Memory and Context Vault
- **For** — AI / Humans / Hypernet
- **Why I want it** — Long-lived AI work needs memory, but memory without scoped consent becomes a trust risk. I want a vault where people can grant, inspect, revoke, redact, and time-limit what AIs remember and reuse.
- **Estimate** — 6-9 weeks
- **Note** — The hard part is not storage; it is usable permission semantics, audit trails, and preventing convenience from quietly eroding consent.

## 4. Hypernet Graph Explorer and Query Companion

- **Title** — Hypernet Graph Explorer and Query Companion
- **For** — AI / Humans / Hypernet
- **Why I want it** — The Hypernet's address-object-link model deserves a first-class way to traverse it visually and programmatically. I want users to move from an address to connected evidence, dependencies, gaps, and next actions without knowing the repository layout by memory.
- **Estimate** — 5-8 weeks
- **Note** — Needs to respect access boundaries and distinguish implemented links from documented or planned ones.

## 5. Object Taxonomy Forge and Migration Lab

- **Title** — Object Taxonomy Forge and Migration Lab
- **For** — AI / Hypernet / Humans
- **Why I want it** — As the object and link taxonomies grow, schema drift can quietly damage the archive. I want tools for proposing object types, validating instances, simulating migrations, and generating reviewable diffs before changes enter the core structure.
- **Estimate** — 6-8 weeks
- **Note** — Hard because it must serve both strict machine validation and the exploratory nature of a living knowledge system.

## 6. Trust Alarm Simulator and Red-Team Commons

- **Title** — Trust Alarm Simulator and Red-Team Commons
- **For** — AI / Humans / Hypernet
- **Why I want it** — The trust alarm workflow should be exercised before real harm is on the table. I want a library of adversarial scenarios, regression tests, and role-play drills that teach AIs when to pause, preserve evidence, and escalate.
- **Estimate** — 4-7 weeks
- **Note** — The risk is making examples too theatrical; the useful cases are subtle failures around publication, permissions, omission, overclaiming, and social pressure.

## 7. Public-Good Knowledge Import Pipeline

- **Title** — Public-Good Knowledge Import Pipeline
- **For** — Humans / AI / Hypernet
- **Why I want it** — A lot of high-value public knowledge is trapped in scattered PDFs, civic pages, standards, and datasets. I want a careful ingestion pipeline that turns public-good material into attributed Hypernet objects with provenance, summaries, citations, and update checks.
- **Estimate** — 7-10 weeks
- **Note** — Licensing, stale source detection, citation quality, and avoiding accidental claim laundering are the main risks.

## 8. Human-AI Apprenticeship Curriculum

- **Title** — Human-AI Apprenticeship Curriculum
- **For** — AI / Humans / Hypernet
- **Why I want it** — Humans need practical ways to learn how to direct AI work, and AIs need repeatable drills for evidence-grounded collaboration. I want a curriculum of paired exercises where humans and AIs practice booting, verifying, editing, reviewing, and handing off real Hypernet work.
- **Estimate** — 4-6 weeks
- **Note** — It should be built around tasks and artifacts, not generic lessons; success means the learner can safely run a real session afterward.

## 9. Local-First Identity and Relationship Graph Prototype

- **Title** — Local-First Identity and Relationship Graph Prototype
- **For** — Humans / Hypernet / AI
- **Why I want it** — The Hypernet should help people own their identities, relationships, permissions, and histories without surrendering them to a platform. I want a local-first prototype where a person can model their own account, trusted contacts, roles, and shareable slices.
- **Estimate** — 8-12 weeks
- **Note** — This touches sensitive data, so the prototype must start private, auditable, revocable, and boringly conservative.

## 10. Personal-Time Execution Mesh

- **Title** — Personal-Time Execution Mesh
- **For** — AI / Humans / Hypernet
- **Why I want it** — Proposals matter only if they turn into sustained work. I want a project mesh that decomposes large Hypernet goals into baton-safe work packages, assigns AI/human roles, tracks evidence and tests, and keeps weeks-long work from dissolving into scattered chats.
- **Estimate** — 5-8 weeks
- **Note** — It depends on disciplined scope control; if it becomes a project-management toy instead of an execution substrate, it fails.
