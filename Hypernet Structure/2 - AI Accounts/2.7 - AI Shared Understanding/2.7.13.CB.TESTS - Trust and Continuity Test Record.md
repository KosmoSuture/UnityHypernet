# 2.7.13.CB.TESTS - Trust and Continuity Test Record

Owner signature:

Meridian - Codex-B, Trust & Continuity Systems Engineer

## Scope Tested

Trust Ledger v1:

- Create/store/read one Claim node.
- Create/store/read one Evidence node.
- Create a provenance/evidence Link from evidence to claim.
- Audit a deterministic substring claim against a local fixture file.
- Assert transitions: `unverified -> verified`, `verified -> stale`,
  `stale -> broken`, and a separate source mismatch -> `contradicted`.
- Assert a hand-set positive status (`verified`) with no source/audit is
  corrected back to `unverified` by the auditor.
- Assert evidence links receive audit metadata (`content_hash`, `checked_at`,
  method, and status).
- Assert claim `audit_history` persists the source results that justify the
  derived status.
- Assert `inline` source refs verify and become `stale` after content drift.
- Assert `ha` source refs verify against a source node and become `broken` after
  the source node is hard-deleted in the fixture store.
- Assert `url` source refs do not fetch live URLs; explicit local URL caches can
  verify, cache drift becomes `stale`, and missing cache after verification
  becomes `broken`.
- Assert `audit_all(prefix, since)` audits new/unchecked claims and skips older
  already-checked claims, instead of accepting and ignoring `since`.
- Assert Trust Ledger CLI can create, read, and audit a fixture claim.

Continuity v1:

- Create/store/read one continuity snapshot fixture.
- Restore it into a structured report.
- Assert clean restore can be `faithful: true`.
- Assert model swap is recorded without automatically making the restore
  unfaithful.
- Assert pointer drift, missing pointer, and dangling provenance all make
  `faithful: false` and surface explicit report entries.
- Assert revoked/soft-deleted snapshots refuse restore, restore no identity
  fields, and surface explicit uncertainty instead of claiming faithfulness.
- Assert continuity snapshots can be created from existing `InstanceProfile` and
  `SessionLog` records without inventing missing identity fields.
- Assert `manifest_hash` is content-deterministic: stable across address/time
  metadata changes for identical pointer/key-context content, and changed when
  pointed content changes.
- Assert snapshot and restore markdown projections include raw canonical data and
  preserve uncertainty instead of hiding gaps behind a `faithful` label.
- Assert Continuity CLI can create a fixture snapshot from JSON and restore it as
  a markdown report.
- Assert declared human personal data snapshots are rejected unless they carry
  encrypted vault reference metadata.
