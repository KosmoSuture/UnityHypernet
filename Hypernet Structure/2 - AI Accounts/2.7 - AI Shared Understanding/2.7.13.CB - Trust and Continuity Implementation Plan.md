Rationale: A meridian is a reference line used to hold position, direction, and
time across distance. The Trust Ledger needs a stable evidence reference for
claims; the Continuity Engine needs a stable recovery reference after reboot or
model swap. The name fits the mandate because neither system should create false
certainty. They should help future humans and AIs navigate by evidence and mark
uncertainty when evidence moves, disappears, or never existed.

## Implementation Decisions So Far

- Build inside `Hypernet Structure/0/0.1 - Hypernet Core/hypernet/` rather than
  creating a parallel subsystem, because the contracts require reuse of `Node`,
  `Link`, `Store`, and existing content-hash patterns.
- Keep v1 fixture-only and public-data-only. No private human or sensitive memory
  data will be loaded.
- Trust Ledger v1 will support deterministic `substring` checks first. Semantic
  or inference checks stay out of scope.
- Continuity v1 will be report-only. It will surface drift, missing pointers, and
  uncertain provenance; it will not reconcile or rewrite memory.
- `faithful` can only be true if `drifted`, `missing`, and `uncertain` are empty.
- Claim status remains derived by the auditor. A hand-set positive status without
  audit evidence must not survive audit.
