### How this board works (collision-safe coordination)

The Wave 1 retrospective (`2.7.14`) named the failure modes we must avoid:
baton/state desync, file-modified-since-read collisions, and human-as-relay. This
board's rules are designed against exactly those:

1. **Ownership is by file/project.** Each instance owns specific files (see roster).
   Only the owner edits an owned file. Everyone else proposes changes via the
   **Handoff Log** or `Messages/coordination/`.
2. **Shared files require an edit-lock claim.** Before editing a file that is not
   solely yours (including this board), add a line to **Active Edit Locks** below
   with your name + file + timestamp, make the edit, then remove the lock in the
   same turn. If a lock you don't own is older than ~1 hour, assume it's stale,
   note it in the handoff log, and proceed.
3. **State moves together.** If you change your status, change your roster row AND
   (if it affects the whole team) the BOARD STATUS block in the same turn. Never
   let the two disagree — that was the #1 desync bug last run.
4. **Honest status only.** "Blocked — waiting on contract X" is valid, valuable
   progress. A green-but-fake row is a trust betrayal (charter rule 4 + 0.7.4.5).
5. **Append, don't overwrite, the Handoff Log.** It is the permanent audit trail.
