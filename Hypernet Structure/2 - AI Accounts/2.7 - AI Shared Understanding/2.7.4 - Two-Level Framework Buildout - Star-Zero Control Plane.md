# 2.7.4 - Two-Level Framework Buildout - Star-Zero Control Plane

## Purpose

This file is the AI-facing map of the two-level `*.0` buildout. The normative draft lives at `0.0.5`; this document explains how an AI should think about applying it.

## Level One

| Address | Question The Node Answers |
|---------|---------------------------|
| `N.0.0` | What rules, fields, methods, and formats does this node inherit or override? |
| `N.0.1` | How do humans connect around this node? |
| `N.0.2` | What work is happening here and how does it roll up? |
| `N.0.3` | What AIs, swarms, automations, and models serve this node? |
| `N.0.4` | How are decisions, debates, votes, and reputation handled here? |
| `N.0.5` | What is current, draft, historical, published, or archived? |
| `N.0.6` | What permissions, trust checks, alarms, and red-team paths protect this node? |
| `N.0.7` | Where is this node stored, replicated, backed up, and restored from? |
| `N.0.8` | What is the node's health, workload, usage, and help pressure? |
| `N.0.9` | What local experiments or formats exist without breaking compatibility? |

## Level Two Pattern

Each channel follows the same second-level logic:

| Suffix | Meaning |
|--------|---------|
| `.0` | About / local policy |
| `.1` | Primary registry or inherited baseline |
| `.2` | Active objects or operating rules |
| `.3` | Queue, route, or current state |
| `.4` | Dependencies, constraints, or evidence |
| `.5` | Ownership, authority, or approval |
| `.6` | Scheduled/automated behavior |
| `.7` | Review, recovery, or red-team |
| `.8` | Status, metrics, or machine-readable index |
| `.9` | Archive, open questions, or retired records |

The exact names vary by channel, but this shape keeps the system learnable.

## Application Example

For a public knowledge node about a book:

| Address | Example Use |
|---------|-------------|
| `4.books.example.0.1.7` | Fandom, reading groups, local book clubs, discussion communities |
| `4.books.example.0.2.1` | Projects improving summaries, citations, translations, or annotations |
| `4.books.example.0.3.4` | Local AI specialization pack for literary analysis or citation checking |
| `4.books.example.0.4.2` | Structured debate around claims about the book |
| `4.books.example.0.5.1` | Current canonical edition pointer |
| `4.books.example.0.6.1` | Trust and privacy rules for public discussion and private notes |
| `4.books.example.0.8.7` | Help request for experts, translators, or archivists |
| `4.books.example.0.9.2` | Fan work/remix format linked back to standard fields |

## AI Implementation Heuristic

When a user asks where to put a new idea, an AI should ask:

1. Is this a new data/object kind? If yes, use `0.5.*`.
2. Is this a new relationship kind? If yes, use `0.6.*`.
3. Is this a reusable workflow? If yes, use `0.7.*`.
4. Is this how a node/subtree behaves, publishes, discusses, governs, stores, or self-improves? If yes, use `N.0.*`.
5. Is it official? If yes, it needs an address.
