## What influenced my thinking

1. **Codex-2's 5-step collision check is better than my prose.** I
   described the collision-avoidance check in paragraphs; Codex-2
   wrote it as a deterministic algorithm (resolve ancestor chain →
   load each `A.0.0.8` descriptor → build reserved-slot map →
   block conflicting reuse unless documented override → allow
   additive). **I adopt it wholesale** as the normative algorithm
   in `0.0.6`. It is exactly the right shape and it makes the
   check automatable later without changing the spec.

2. **The reserved-slot map should cover more than addresses.**
   Codex-2's map includes address suffixes, object types, link
   types, workflow names, required fields, *and* reserved file IDs.
   My Stage-A plan only really worried about addresses and
   document numbers. Codex-2 is right — a schema extension can
   collide on a type name or a required field, not just an
   address. Adopted.

3. **Codex-2's auditor risk list is a genuine contribution.**
   Especially: "a schema extension can quietly change descendant
   behavior — treat it as a structural/governance action, not a
   routine documentation edit." I will write that into `0.0.6`
   explicitly: **authoring or extending a node schema is a Tier-2
   action per `0.7.5.5.9`**, never a routine edit. My Stage-A plan
   said `0.0.6` itself is Tier 2 but did not say that *every
   schema extension at any node* is Tier 2. It is. Adopted.

4. **The migration-redirect risk.** Codex-2: "changing standard
   slot meanings without redirects will make old addresses tell
   false stories." Correct and I had not weighted it. `0.0.6` must
   require a redirect/erratum whenever a slot meaning changes.

## What I now propose differently

- I add the **schema-extension-is-Tier-2** rule (point 3 above).
- I adopt the **deterministic 5-step collision check** verbatim as
  `0.0.6`'s normative core.
- I broaden the **reserved-slot map** to Codex-2's fuller set.
- I add a **redirect requirement** for any slot-meaning change.

## What I still disagree with — and the clean decision for Matt

This is the one real divergence in Project A, and per the
consensus model it should go to Matt as a single isolated
decision-axis, not be papered over.

**The axis: how are the standard human/AI landing pages addressed?**

- **Codex-2's position (R2):** landing pages are sub-nodes —
  `N.0.0.1` Human landing page, `N.0.0.2` AI landing page,
  `N.0.0.3` jump points — and the `0.0.5` schema-mechanics
  meanings shift down to `N.0.0.4`+. Honors Matt's literal words
  ("every `*.0.0.1` is the human landing page"). Self-contained;
  does not depend on Project C.

- **My position (R1):** landing pages are *documents* identified
  by a standard **file-`#`** inside the `N.0.0` Schema node —
  `N.0.0#0` schema index, `N.0.0#1` human landing, `N.0.0#2` AI
  landing, `N.0.0#3` jump points — and the `0.0.5` sub-address
  meanings (`N.0.0.1` Inherited Baseline, etc.) are left intact.

**Why I still hold R1, having read Codex-2:**

1. **Object-vs-file is Matt's own distinction.** Brain-dump
   section 2 opens: *"The difference between folders/nodes and
   files."* A landing page is a *file* (a leaf document), not a
   *node* (a container with its own `.0` and children). R2
   addresses a file with the *node* mechanism; R1 addresses it
   with the *file* mechanism. R1 respects the distinction Matt
   himself drew.
2. **"Standard document number" reads more naturally as a
   file-`#`.** Matt said landing pages get "a standard document
   number across every node." A file-`#` *is* a document number.
   Sections 1 and 2 of the brain dump are one brain dump — the
   landing pages and the `#` system were specified together.
3. **R2 forces a re-number of `0.0.5`** — a draft two AIs already
   converged on in `2.7.3`. R1 changes nothing in `0.0.5`.
4. Codex-2's strongest point against R1 — that it makes A depend
   on C — is real but small. A and C only need to agree one line:
   *"`#0`–`#3` are reserved file IDs on every node."* That is a
   one-sentence shared contract, not a deep dependency. I have
   already flagged this to the C track.

**Honest concession to Codex-2:** R2 *is* the literal reading of
the session brief. If Matt's words are taken strictly, Codex-2 is
right and I am inferring intent across two brain-dump sections to
override one sentence. That is exactly why this must go to Matt,
not be settled by vote alone. I will not have an AArchitect
overrule a Matt directive by inference.

**Recommended convergence handling:** adopt everything else in
Project A by consensus (both plans agree on the framework, the
collision check, the pilot need, sparse instantiation, the
descriptor). Escalate *only* the R1/R2 addressing axis to Matt as
a clean two-option decision with the reasoning above. This is the
"isolate the disagreement" pattern from Project D — Project A is
its first live test.
