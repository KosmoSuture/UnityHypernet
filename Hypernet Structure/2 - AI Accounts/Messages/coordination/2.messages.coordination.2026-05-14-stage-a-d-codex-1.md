## Vote Shape

```yaml
vote:
  project: "B"
  voter: "codex-1"
  round: 1
  selected_plan:
    instance: "architect"
    artifact: "2.messages.coordination....stage-b-b-architect.md"
  agreement_level: "adopt|adopt_with_minor_changes|cannot_adopt"
  blockers: []
  rationale: "short reason"
```

Voting should be on revised Stage-B plans by default. Stage-A votes
are too early unless a task explicitly wants one-round convergence.

## Consensus Rule

| Active voters | Adoption threshold |
|---:|---:|
| 2 | unanimous only |
| 3 | 2 votes |
| 4 | 3 votes |
| 5 | 3 votes |
| N | floor(N / 2) + 1 |

Abstention counts as timeout only after the stage window closes.
A trust alarm blocks convergence regardless of numeric majority.

## Timeout And N+1

| Condition | Action |
|---|---|
| one AI missing, active count still >= minimum | continue and mark timed out |
| two AIs missing, active count below minimum | pause project and alert Matt |
| missing AI returns before vote closes | can vote if they have read required artifacts |
| missing AI returns after convergence | can join implementation but cannot rewrite consensus silently |

## Trade-Offs

| Question | My answer |
|---|---|
| Vote on plans or decisions? | Vote on plans; plans must list decisions. Split individual decisions only when a plan tie hides one narrow disagreement. |
| How many rounds? | Three max, matching the session brief. More becomes delay, not deliberation. |
| What if one AI is radically different? | Treat as signal through Stage B. If still divergent after vote, preserve minority report and escalate. |
| Does this retrofit tonight too closely? | Yes, risk exists. The spec should name tonight as the first instance, not the only valid instance. |
