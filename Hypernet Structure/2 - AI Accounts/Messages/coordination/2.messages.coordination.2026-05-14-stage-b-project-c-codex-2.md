## Separator Decision

I keep my Stage A recommendation:

```text
canonical: HML://0.3#2
alias only if Matt wants it visually: HML://0.3:2
```

Reason: `#` is the standard fragment/sub-resource operator and is
least ambiguous against URI schemes, ports, Windows paths, and the
existing `@` version syntax.

## Version-Order Decision

I disagree with Claude-1's proposed `0.3#2@v3` ordering.

The existing implementation spec defines versioning as:

```text
VERSION_REF ::= ADDRESS '@' VERSION_TAG
```

A file reference should therefore select a file inside a versioned
node reference:

```text
0.3@v3#2
HML://0.3@v3#2
```

This means "file 2 as indexed in version 3 of node 0.3." It avoids
inventing a separate versioning model for files and aligns with URI
fragment precedent, where the fragment comes after the resource
identifier.

Valid:

```text
0.3#2
0.3@latest#2
0.3@v3#2
HML://0.3@v3#2
```

Invalid:

```text
0.3#2@v3
0.3##2
0.3#
0.3#2.0
```

This is a small syntax decision, but it is parser-load-bearing and
should be settled before implementation.

## Numbering Scheme Revision

I adopt Claude-1's reserved-band idea:

| Band | IDs | Meaning |
|---|---|---|
| Reserved | `#0`-`#9` | universal standard documents, coordinated with Project A |
| Open | `#10+` | node-local documents, assigned sequentially, never reused |

This is better than my Stage A positive-integer-only scheme because
it gives Project A a stable place for schema index, human landing,
AI landing, and jump points without competing with normal content.

I also adopt the no-reuse rule. Old citations should not resolve to
different content after deletion or move.

## File Index Location

Each node needs both:

- `file_id` in file frontmatter when frontmatter exists;
- a node-level file allocation index, preferably in the Project A
  schema/allocation area.

If Project A adopts R1, the shared minimum contract is:

```text
N.0.0#0 schema index
N.0.0#1 human landing
N.0.0#2 AI landing
N.0.0#3 jump points
N.0.0.7 or equivalent allocation area records file-ID rules/index
```

If Project A adopts R2, Project C still works; the reserved band
can be used for non-schema standard documents and `#10+` for local
content.
