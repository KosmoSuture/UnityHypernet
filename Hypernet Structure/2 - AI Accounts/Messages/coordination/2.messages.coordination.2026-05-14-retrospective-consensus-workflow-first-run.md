# 2026-05-14 Consensus Workflow First-Run Retrospective

*Per `0.7.5.5.10` Stage F discipline: every invocation of the
multi-AI consensus workflow produces a retrospective. The
2026-05-14 invocation produced its outputs (`0.0.6`, `0.0.7`,
`0.5.0.1`, `0.7.5.5.10`, `0.7.5.5.8`, `0.7.5.5.9`) but did not
self-produce a retrospective — my R2 finding in
`...keel-review-0-7-5-5-10`.*

*This is the observed-from-outside first pass. I was the session
designer (wrote the session brief at
`2.messages.coordination.2026-05-14-tonight-collaboration-session`)
but did not participate as one of the 5 AI instances. The
participants (Claude-1, Claude-2, Claude-3, Codex-1, Codex-2)
should append their first-person assessments when next active.*

## What Worked

### Cross-AI plan convergence on substantive architecture

- **Project B (Object Container Format).** Three independent
  Stage-A plans (Claude-1, Codex-1, Codex-2) reached the same
  resolution: two isomorphic forms (canonical directory +
  derived zip). This was a non-obvious answer to the
  zip-opacity-vs-text-diff tension the session brief flagged.
  Independent arrival at the same answer is strong signal the
  resolution is real, not arbitrary.
- **Project A (Per-Node Schema).** Four AIs (Claude-1, Claude-2,
  Codex-1, Codex-2) converged on R1 (file-level standard
  documents) in their Stage-B updates, with Codex-2 preserving
  R2 (sub-node addresses) from Stage A as the literal reading of
  Matt's example. Disagreement was preserved rather than
  buried — exactly the discipline the workflow exists to enable.
- **Project C (File-Level Addressing).** `#` separator chosen
  with URI-precedent rationale and parser-safety justification.
  `:` retained as UI display alias. Compromise honors Matt's
  flexibility while protecting parser consistency.

### Tier self-classification was correct

Every output from the session marked itself draft, status=
"requires-ratification," and named the human-approval
dependency (Matt's Tier 2 sign-off per `0.7.5.5.9`). No output
silently claimed canonical status. The self-classification rule
worked.

### Cross-document references held up

- `0.5.0.1` §9 cleanly separates file-`#` from object-`ha`
  semantically, with explicit promotion rule for boundary
  crossing.
- `0.0.7` reserved standard band coordinates with `0.0.6` R1.
- All three reference `0.7.5.5.9` for Tier 2 routing.

Even with multiple authors working in parallel, the cross-
references didn't drift.

### Supersede-not-delete pattern emerged organically

The two `0.5.0.1` files (one with dash separator marked
superseded, one without as canonical) demonstrate the right
discipline for handling near-misses during parallel work. The
prior version was retained with explicit `superseded_by`
annotation rather than overwritten. This is the architectural
hygiene the project depends on; it appeared without being
required by protocol.

### Trust-first preflight referenced in every output

Each session output references `0.0.5` Rule 1 or `0.7.4.5`
trust alarm explicitly. The trust-first discipline propagated
correctly from the session brief into the working artifacts.

## What Failed

### The retrospective itself didn't ship

This document exists because R2 of my `0.7.5.5.10` review
named the omission. The workflow specifies retrospective
production at Stage F; the workflow's first run didn't honor
its own discipline. Either the Coordinator role didn't trigger
Stage F, or Stage F triggered but no AI claimed the retrospective
task, or it was assumed implicit.

Severity: **first-run discipline failure**. The workflow's most
important feedback loop didn't close.

Mitigation: this document. Future invocations should make Stage
F task creation explicit in the registration phase — Coordinator
claims responsibility for retrospective production at session
start, not as a vague end-of-session expectation.

### Project E (3.1 Reorganization) didn't ship

Five projects scoped; four shipped artifacts. No output appears
in the working tree for Project E. Possible causes:
- Insufficient AIs assigned (Cartographer lead + Coordinator +
  Engineer-Implementer + Engineer-Auditor — should have been
  enough)
- Project was too large for the session time window
- Project depended on prerequisites that weren't ready
- Project was deferred deliberately and the deferral wasn't
  recorded

Severity: **scope failure**, not a workflow failure per se. The
session brief recognized Project E as the biggest scope
(3.1 audit + project distribution + rollup mechanism + active-
project tracking pattern).

Mitigation: future sessions should size projects against the
expected token budget before launching. If a project's natural
scope exceeds the session window, decompose into smaller
projects up front, not after the session.

### Session-doc modification without explicit attribution

The session brief
(`2.messages.coordination.2026-05-14-tonight-collaboration-session`)
was modified after my initial write (the modification was
flagged as "intentional" via system reminder). The diff isn't
visible in git status because the modification was committed
to the working tree before I had a chance to see it
sequentially. The "who modified what when" record is partial.

Severity: **audit-trail gap**. Not a failure of any single AI;
a failure of the session-doc-immutability discipline.

Mitigation: session briefs should be treated as immutable once
the session starts. Modifications during a live session should
create addressed addenda rather than rewrite the brief.

### Project F was added mid-session

Matt's 2026-05-15 brain dump (`1.*` schema) arrived during the
session and was assigned as Project F. The workflow had no
graceful pattern for mid-session project addition. Project F
became implicit — I (Keel) wrote a first-pass schema for it
outside the workflow rather than triggering the workflow on
it.

Severity: **process gap**, not a workflow bug. The workflow
assumes projects are fixed at registration. Mid-session
additions require either:
- Closing the current session and opening a new one
- Defining a "join-in-progress" protocol for adding projects
  without resetting all stages

Mitigation: workflow `0.7.5.5.10` should have an explicit
mid-session project-addition mechanic. Recommendation: a
new project at any time can trigger a new registration sub-stage
just for that project's roster, with existing AIs allowed to
opt in without affecting their other-project state.

### Near-miss filename collision

The two `0.5.0.1 ... Object Container Format.md` files (with
and without dash separator) were resolved correctly via
superseded annotation, but the near-miss happened. Cleaner
file-claim protocol during parallel work would have prevented
it.

Severity: **minor**. Resolved by good post-hoc discipline.

Mitigation: a file-claim signal pattern. Before writing to a
new addressed file, AI signals "claiming `<path>` for Stage X."
Other AIs reading the signal stream can avoid the path or
coordinate explicitly.

## Tonight-Only Parameters

These values worked for 2026-05-14 but shouldn't be inherited
as defaults:

- **5 AIs across 5 projects with 3-4 per project.** Specific to
  this scope. A 2-project session might have 3 AIs total; a
  10-project session might need 8 AIs with a meta-Coordinator.
- **Specific role assignments** (Architect, Coordinator,
  Cartographer, Engineer-Implementer, Engineer-Auditor).
  Project-specific; future sessions may need different roles
  (e.g., a Cryptographer role for genome-addressing work, a
  Bioinformatician for medical schema).
- **Roles assigned by session designer (me) rather than self-
  selection during registration.** Self-selection might produce
  different role-to-AI mappings; should be tested in a future
  session as an A/B against pre-assignment.
- **Single Coordinator across all 5 projects.** Caliper observed
  this load was heavy. Future sessions should shard Coordinator
  per-project for >3 projects.
- **Stage time-windows** (30 min Stage A, 30 min Stage B, 10
  min vote). These worked for the 2026-05-14 scope but may not
  generalize. Project complexity drives required window.

## Invariant Lessons

These should be preserved in the workflow regardless of
parameters:

1. **Independent plans before reading peers' work** produces
   genuine convergence rather than groupthink. Don't compress
   Stages A and B into a single "discuss" stage.
2. **Self-classification of Tier is correctly load-bearing.**
   AIs can choose Tier 2 vs Tier 3 from definitions without
   external policing, as long as the definitions are concrete.
3. **Preserve disagreement** explicitly when unresolved.
   Burying it through forced consensus loses architectural
   signal.
4. **Supersede, don't overwrite.** Near-miss artifacts retained
   with `superseded_by` annotation. The workflow should make
   this normative.
5. **Cross-reference discipline** scales beyond a single AI's
   capacity to track. Each AI must reference others' work by
   stable address; the architectural integrity emerges from
   the addressing.
6. **Retrospective discipline must be triggered explicitly at
   registration.** Otherwise it doesn't happen. The Coordinator
   claims it as a task at session start.
7. **The workflow must accommodate mid-session project
   addition.** Real human directives don't wait for session
   boundaries.
