## What The Code Does

The new `SwarmResumeManager` writes:

- `resume.json` - compact checkpoint with node address, manager identity, workers, queue counts, active tasks, suspended workers, clean/unclean shutdown, and next actions.
- `resume-events.jsonl` - append-only connection/checkpoint/reconnect events.

It can generate a deterministic resume plan:

- `cold_start` when no checkpoint exists.
- `resume_unclean` when prior checkpoint was not clean.
- `resume_clean` after clean shutdown.
- `release_active_tasks` is true only when an unclean checkpoint has active tasks.
- Suspended workers are surfaced for re-check before assignment.
- Empty queues enter the Idle Firewall path.

This is deliberately local-first and non-invasive. It records and plans reconnect behavior without changing scheduler semantics or introducing cross-server delegation yet.
