## The Consensus Workflow (in use this session)

Per Matt's brain dump section 3. Each project runs this workflow
in parallel. Stages are time-boxed.

### Phase 1: Registration (15 minutes)

Each AI:
- Reads this session doc and the brain dump
- Confirms their assigned role
- Posts a signal in the coordination channel announcing
  "Instance X reporting as [Role]; claiming Projects [A, B, ...]"
- Identifies any concerns about role fit; flag if any role is
  unstaffed or over-staffed

### Phase 2: Independent Plans (Stage A — 60 minutes)

For each project, every AI assigned to it writes their own
plan, independently, without reading other AIs' plans:

- Plan should include: their reading of the goal, what they'd
  build, what trade-offs they see, what they'd ask Matt before
  starting
- Plans are addressed Markdown files at
  `2.messages.coordination/2026-05-14-stage-a-<project>-<instance>.md`
- Each AI also reads what the *other AIs are not seeing* — i.e.,
  whatever public-track context the brain dump references but
  doesn't explain

### Phase 3: Cross-Read and Revise (Stage B — 60 minutes)

Once all Stage-A plans for a project are in:

- Each AI reads every other AI's plan for that project
- Each AI writes a *revised* plan explaining:
  - Which points from other AIs influenced their thinking
  - What they'd now propose differently
  - What they still disagree with and why
- Revised plans live at `2.messages.coordination/2026-05-14-stage-b-<project>-<instance>.md`

### Phase 4: Vote (Stage C — 30 minutes)

Each AI casts one vote per project, naming the *other* AI's plan
they'd most prefer to adopt (cannot vote for own plan).

- Votes live at `2.messages.coordination/2026-05-14-vote-<project>-<instance>.md`
- Tally is calculated by Coordinator role

### Phase 5: Convergence (Stage D — variable)

- If one plan has clear majority → adopt as basis for
  implementation
- If split → write Stage-B-prime: another revision cycle (max
  3 cycles per project)
- If still split after 3 cycles → escalate to Matt with full
  history, both leading plans, and explicit naming of where
  reasonable AIs disagree

### Phase 6: Implementation (Stage E — open-ended)

The winning plan is implemented. All AIs on the project may
contribute. Implementation produces real files at real
addresses, not just plans about plans.

### N+1 Redundancy

Each project has 3-4 AIs. If one fully times out under the
dropout rule below, the project continues with the remaining AIs.
If two fully time out and project has <=2 active, that project
pauses pending Matt's attention.

For this run, do not assume an AI has dropped out unless both are
true:

- the AI has been silent for at least 15 minutes; and
- at least one 15-minute project check-in tick has explicitly
  looked for active participants and recorded the missing signal.

A missed tick means `needs-checkin` first, not automatic dropout.
If an AI returns and has read the required artifacts, work with the
returning AI rather than treating earlier silence as permanent.

### Timeout Per Stage

Default per-stage timeouts:
- Registration: 15 min
- Stage A (independent plans): 60 min
- Stage B (cross-read/revise): 60 min
- Stage C (vote): 30 min
- Convergence retry: 45 min per cycle
- Implementation: open-ended, with check-ins every 15 min

AIs should signal "I am still working" if they need more time;
silence alone is not dropout until the 15-minute silence plus
15-minute check-in-tick rule above has been satisfied.
