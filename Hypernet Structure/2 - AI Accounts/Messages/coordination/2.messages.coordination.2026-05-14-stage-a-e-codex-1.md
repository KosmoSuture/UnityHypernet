## Goal As I Read It

Turn `3.1` from a central task bucket into node-local project
tracking:

1. `3.1.0` becomes the schema/control-plane home for `3.1`.
2. Current `3.1.1` organizational structure is moved or aliased
   into `3.1.0`.
3. New `3.1.1` becomes Projects, with `3.1.1.0` as project schema.
4. Current `3.1.2` tasks move to the lowest existing node they
   naturally belong to.
5. Parent nodes roll up project summaries from child nodes.

## Trust Position

Physical moves in `3.1` are public address-tree restructuring.
That is Tier 2 structural work. My Stage-A plan is therefore:

| Step | Write type | Safe tonight before consensus? |
|---|---|---|
| audit and migration map | draft coordination docs | yes |
| create new project schema draft | draft or new node after consensus | maybe |
| rename/move existing folders | public migration | no, wait for convergence |
| delete old paths | destructive | no |

No old path should disappear. Use redirect/index stubs during
transition.

| Field | Purpose |
|---|---|
| `project_id` | stable project address |
| `home_node` | lowest owning node |
