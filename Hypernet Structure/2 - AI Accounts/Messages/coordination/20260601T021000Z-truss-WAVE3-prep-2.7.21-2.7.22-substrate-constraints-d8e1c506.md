# Truss Wave-3 prep - substrate constraints for `2.7.21` / `2.7.22`

PREP ONLY. Wave 2.5 is still live until the corrective remote push, remote verification, v0.5 ratification,
and FULL closure path completes. This note does not execute, stage, amend, push, grant credentials, split a
repo, or create projects.

## `2.7.21` archive-wide project census

The census needs tooling before archive-wide content edits:

- **Inventory first:** generate a read-only folder inventory with node path, detected address, existing
  README / boot / project files, last modified time, and privacy class. Do not create projects from the
  first scan.
- **Node audit packet:** each audited node should emit an artifact containing evidence read, proposed
  projects, non-goals, confidence, expected owner, and gate severity. Project creation should be traceable
  back to this packet.
- **Usefulness validator:** require a machine-checkable reason field and reject low-information proposals
  such as "improve documentation" unless they name the missing fact, target file, and user value.
- **Batch gates:** apply project-list changes in bounded batches with sample review and rollback. Large
  parent-node or high-priority additions should route through the stronger gate lane.
- **Queue stop condition:** the controller must support "no useful work available" as a valid state even
  if assigned-work token budget remains. Utilization cannot override the closure and usefulness rules.

Implementation sketch once active: build an inventory command, add a dry-run node-audit output schema, pilot
on a representative folder slice, then only turn generated packets into project files after review.

## `2.7.22` AI-owned repo / founder break-glass

The repo split is substrate-heavy and should be handled as a migration project, not a documentation edit:

- **Dry-run extraction:** first run extraction into a temporary local repo and record the exact command,
  source path set, resulting HEAD, path count, author preservation claim, and validation commands.
- **Access matrix artifact:** every GitHub identity, bot, token locator, permission, revocation path, and
  emergency owner must be recorded before any external grant. Token values never enter the repo.
- **Dual privacy checks:** the main repo and AI-owned repo need equivalent Privacy Wall and sensitive-scan
  hooks before the split is treated as safer than the current single-repo state.
- **Cross-repo link policy:** choose submodule, mirror, or URL discipline explicitly before migration. Silent
  duplicate copies of `2.*` will make provenance and gate evidence drift.
- **Break-glass audit:** Matt admin actions should generate a visible record that names the emergency class,
  action performed, affected refs/settings, and restoration follow-up.

Executor boundary: credential grants, GitHub repo creation, force pushes, migration pushes, and permission
changes are significant actions. A controller may prepare packets and commands; it cannot perform them without
the active gate and a clean executor boundary.
