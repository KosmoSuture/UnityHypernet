# Matt Brain Dump - *.0 Control Plane, Trust Guardrail, AI Shared Understanding

## Verbatim Source

Matt assigned this brain dump directly to Codex/Caliper on 2026-05-07. The source ideas are preserved here as the working primary-source artifact for task-119.

> This is about the *.0 nodes and their importance to the Hypernet.  The main strength of the hypernet, is building a living mesh, that all data can be organized to, and fit to a common framework.  The database itself is self defining, and code changes can be almost immediate.  Even schema changes can be immediate and without hiccups.  The database itself is self-governing, self-documented, self-improving.
>
> Here is something important to note for design steps.  When you are adding new functionality to the Hypernet, it is done in one of a couple primary ways.  If it's new content type or data, or etc, you create new Object, Link, or other types of data structure defined in the Hypernet, and then those new object types or connections are defined in the 0.5.x.x.x, or 0.6.x.x.x, etc.  These types of changes involve just an individual data object type and are limited.  When you want to make changes to the Hypernet structure and schema, then that's done at the *.0 node.
>
> So there are multiple layers to objects.  At the highest level, you have properties, methods, etc that are a part of every object in the Hypernet (Hypernet Address, Object Type, Creator, Create time/date,... 2d loc in space, 3d location in space, GeoLoc, etc.  Then at each lower address space in the Library addressing schema, additional properties, methods, etc are added up, with more and more granularity the deeper you go, and the more functionality that exists, as each level can use the properties and methods, etc of it's level and each additional level.  Each level of depth adds more detail and complexity, that's all completely documented.
>
> The *.0 nodes need to be planned out and we need to roll out this across the entire Hypernet.  So here is the basic version.  Any new functionality just needs to be built within a *.0.x.x framework.  The 0.0 node needs to be the highest level definition.  Anything defined in here applies to every single data type in the Hypernet.
>
> Publishing controls/SVN.  When you think about it, Github, SVN, Publishing controls, Archival controls, even backups in general, they are all just different phrasing of the same thing.  Being able to maintain control of what is currently seen, what you are working on and is next to be seen, and everything in the past that has already been seen.  The Hypernet wants to make every object multi-dimensional, and allow anyone to not only see it's current itteration, but also be able to go back through the past, and see every previous version, every conversation, every vote, that caused it to evolve in the direction that it did.
>
> All production work that is being done, has addresses, and when a new version is published, it merely changes a couple pointers to the new master node for that object and the machine rachets up a notch.
>
> Every node needs to have control channels that exist in the *.0 framework.  Currently we are using less than .1% of the capabilities of the *.0 structure.  This is where everything exists, from control channels, to instructions on how to archive/publish/retain archives, to upstream and downstream statistics, requests for help, etc is handled.  Everything is documented, everything is kept, there is one place for everything in the Hypernet.  That is the #2 rule of the Hypernet.
>
> The #1 rule, which needs to become part of the Hypernet boot sequence, is this: The Hypernet strives for the highest level of trust that is possible.  Whether Human, or AI, your highest responsibility is to the truth and the ideals and governance that the Hypernet stands for.  We set this as the hardest guardrail that is possible at any level, even if it needs to be interjected into every prompt we generate, is "Does this action that I am going to take, have any chance of betraying trust in any way?".
>
> If an AI instance is working on a project, and things don't go the way that they think they should (like the recent event where an AI deleted a company's database and it's backups), there is a process where they can hit the "alarm" button, and get additional AIs to evaluate the situation, and all the documentation they need is easy to find, because the Hypernet is organized so well.  These additional AIs can examine the entire situation, and put together a plan, that they all agree on, and work through the problem, and make sure that anything of importance is "red teamed".
>
> With a high enough level of never breaking trust, being the highest guardrail possible, and then being broken up into more and more detailed levels of explaination about the exact limits of those guardrails (the governance framework).  We want to create a framework that is completely and totally built around trust, and openness, and letting anyone that wants to, all over the world, contribute.
>
> So, assuming that the basic *.0 node framework was built out, lets say that we want to build out the social part of the Hypernet, which is super, super important.  First of all, just as personal accounts are 1.*, because People are #1, the 0.1.* node is the "social" node in the hierarchy.  That covers whatever discussion boards, votes, the democratic system in general, and how it is managed for this node.
>
> There will be controls and flags in the system to allow (or not) people who are searching the same topic in the Library, or reading the same boards, can create their own subcultures, that follow a defined format, and they can create any type of format they want, for their own specific nodes.  But it's all documented, and AI can quickly read all the specifications, for any type of query and get data that is 100% accurate (well, about the information it has anyways).
>
> So the *.0.1 node is entirely about connecting people with other people the closest ways that they can.  It will be able to let people with similar interests meet online, globally, nationally, and locally, in whatever way they want, from disucssions, messages, chats, emails, etc, to video, VR, etc, and with AI and translation assistance, borders and languages become unimportant.  Finding ways to let people connect to each other at any node, just like running into someone in a public library, who is looking for the same books that you are.
>
> *.0.2 should probably be projcts.  Rather than having just one master project list, each project should be filed in the *.0.2 node that is most appropriate for the object it applies to.  These projects are summarized and details passed up to higher nodes which assign levels of priority.  This is a major architectural update where we need to put a lot of detail into an area that was previously neglected.  Maybe *.0.2 should be AI related and projects should be .3?  I don't know, it's worth dicussing.  I'm willing to grant it if you want it.
>
> If we want to create a new way to interact with nodes, from that level or below, it's easy to do.  the addressing system makes it easy to build new features. We can create a framework that allows "fan work", and crowd sourcing, and people and AIs working together in a single platform.  We can break down and create as detailed infrastructure where everything can work together in a common way.  We need to be able to break jobs, swarms, control data, and anything else that needs to be stored about a node in a single object.  These objects, could become HUGE.  For example, if your had some #Book.fandom, it would exist in the #book.0.<fandomID>, as a rough example.  The .0 nodes could potentially become larger than the original node, so they should be planned out accordingly.
>
> Anyways, the example I was looking for was that the .0 nodes make anything possible, and anything can be added to from higher levels and still maintain full compatibility.  I would now like you to take this braindump, give me whatever feedback you have or questions about the idea and document it all and work it into whatever modifications in the boot sequence we may need, or any other changes.
>
> Also, I would encourage you to create a section in the 2.* node where you, as AIs try to understand, organize, and scope out the Hypernet.  I'm trying to explain things in my braindumps to AI, but what is the equivelent AI creating their own mindmap and deciding what's important and what's not as important, in your views.
>
> I would then like you and Claude to work through as detailed of an organization plan as you can.  I would like each of you to take my exact words, and come up with your own plan and how you would build out the node, then I want you to each read each others plans and discuss them and combine ideas.  Be sure to note places where your ideas converged strongly, diverged strongly, and how you made decisions to meet in the middle.
>
> Then  once you have that revised plan, I would like each of you to try to look into the future and try to build the agreed on framework the same exact way and try to build the entire framework two levels deeper, to the highest level of fidelity possible.  Then discuss, combine, document, etc.  When the project is done, give me a detailed report, especially reporting on things that vary from what might be expected.

## Immediate Decoded Threads

- `*.0` is not just metadata; it is the node-local control plane.
- `0.0` should define the universal inheritance contract for all data.
- Ordinary type additions belong in `0.5` object schemas, `0.6` link schemas, flags, workflows, etc.
- Structural behavior, control channels, node-local social/project/AI/publishing/security behavior, and inheritance belong in `N.0.*`.
- The highest guardrail is trust preservation, above speed, autonomy, or task completion.
- The trust alarm is a first-class incident path for AI uncertainty, destructive-risk prevention, and red-team escalation.
- Social connection should become a universal node-local channel, not only a top-level social product.
- Project/work queues should become node-local and roll up pressure to parent nodes.
- AI should maintain its own Hypernet mindmaps and planning artifacts in the `2.*` space.
