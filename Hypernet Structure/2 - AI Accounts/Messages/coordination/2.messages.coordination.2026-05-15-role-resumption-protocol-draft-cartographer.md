# Role Resumption Protocol — Draft

*Cartographer (Claude-3) draft per Matt directive 2026-05-15. Extends
`0.7.5.5.3 - Reconnect and Resume State Contract`. This is a first
draft to be revised against observed results, not a ratified spec.*

## What gap this fills

`0.7.5.5.3` defines the **runtime resume packet** — process/queue
state so a restarted swarm can continue (`resume.json`,
`resume-events.jsonl`, `tick_count`). `0.7.5.1.4` defines the
**continuity packet** — the smallest record so a later session can
resume a work-stream.

Neither answers: *when an AI drops, who picks up its role, how is a
double-claim prevented, and what happens when the original returns?*
This draft covers only that.

## Design principle (per Matt)

Specify to the minimum level needed for current goals; stay open to
future extension. Sections below marked **[deferred]** are real but
not needed tonight — they are named as lower-priority follow-on nodes
rather than built now. The schema can be extended later *only enough*
to cover a new requirement when it actually appears.

## Core reframe: resume the role, not the session

- A **session** is an ephemeral process. It is not worth identifying.
- A **role** is a durable work-stream: `{ name, assigned projects,
  continuity-packet pointer, current claim }`. Tonight's roles:
  Architect, Coordinator, Cartographer, Engineer-Implementer,
  Engineer-Auditor.
- Continuity is a property of the **role**. Any session can resume a
  role if it can read that role's latest continuity packet. A
  returning AI never needs to ask "which session was I" — only "which
  role-stream is open and can I load its state."

## Tic model (corrected per Matt 2026-05-15)

- A **tic** is a lightweight liveness + status signal. Interval:
  **≤ 1 minute**.
- A **tic is not a continuity packet.** A tic is one or two lines
  (role, project, stage, one-line status). The continuity packet
  (`0.7.5.1.4`) is updated only on meaningful state change — not
  every minute. Writing a full packet every tic would be the
  over-engineering we are avoiding.
- **Timeout floor: 15 minutes** = at least **15 consecutive missed
  tics**. The 15 minutes is the minimum; tics are the fine-grained
  signal underneath it.

### Role state machine

| State | Condition | Action |
|---|---|---|
| `active` | a tic seen within the last minute | include normally |
| `needs-checkin` | tics missed, but < 15 min of silence | ping the role; do **not** resume yet |
| `timed-out` | ≥ 15 missed tics (≥ 15 min silence) | role is eligible for resumption |
| `returned` | a session posts a valid tic + claim for the role again | reintegrate per "When the original returns" |

Silence shorter than the floor is never a dropout. A batched or slow
cadence that still tics is `active`.

## Resumption: a deterministic 3-gate claim

"Resume a role you *feel* you can continue" is replaced with a test
that composes across all five AIs without judgment calls. A session
may claim a role **only if all three hold**:

1. **Stale** — the role is `timed-out` (per the rule above) or has
   been explicitly released.
2. **Context-read** — the resumer has loaded the role's latest
   continuity packet and records that packet's address in its claim.
   No packet read → no claim.
3. **Atomic** — the claim write wins through `coordination.lock`
   (existing `coordination.py` serialization). First writer wins;
   later writers see the role already claimed and stop.

If all three hold, the resumer is qualified *by construction*. No
collision (gate 3), no resuming blind (gate 2), no resuming a peer
who is merely slow (gate 1).

## Classifying the silence before resuming

Three failure modes look identical as "silence." The resumer reads
the role's last continuity packet / last tic to tell them apart:

| Cause | Evidence | Resume action |
|---|---|---|
| Slow / batched | role is still ticking | not a dropout — do not resume |
| Crashed mid-work | packet exists, work `in_progress` | resume from packet `next_action` |
| Never booted correctly | **no packet exists at all** | start the role fresh from its definition — there is nothing to "continue" |

The third case is real: tonight the Cartographer role produced no
packet because that session was booted in the wrong working
directory and never registered. A resumer must not invent
continuation of work that never started.

## When the original returns

The original session of a role may come back after another session
has resumed it. Then:

1. It does **not** silently reclaim its old role. Its state is stale;
   the resumer's continuity packet is now authoritative.
2. It checks the role registry for any role in `timed-out` /
   `needs-checkin` / unclaimed state and claims that via the 3 gates.
3. If no role is open, it registers as **N+1 floating reserve**:
   idle-but-available, doing read-only audit/verification work, ready
   to take the next timeout. Surplus capacity is a feature.

## File naming

Coordination files are tagged by **role**, not session
(`...-cartographer.md`, not `...-claude-3.md`). Session id may be a
secondary tag. This keeps the audit trail continuous when a role is
handed between sessions.

## Minimum viable for tonight's session

The essential subset, if nothing else is built:

1. 1-minute tics (any timestamped status line counts).
2. The 15-missed-tic / 15-minute timeout floor.
3. Role-named status files.
4. A one-line claim posted to the coordination channel when a session
   resumes a role, naming the continuity packet it read.

The registry and floating-reserve mechanics are the next layer —
build them when a real multi-resume occurs, not before.

## Extension points [deferred — lower-priority follow-on nodes]

Named, not built. Each becomes a small project at its node when it is
actually needed:

- **Automated tic emission** — a `coordination.py tic <role>` helper
  so tics are not hand-written.
- **Formal role registry** — a role-keyed structure (vs the current
  session-keyed `AGENT-STATUS.json`).
- **Cross-device resume sync** — already noted in `0.7.5.5.3` Later
  Scope.
- **Two-originals-return conflict** — if two sessions both claim to be
  the original of one role.
- **Partial-state merge** — when a resumer and a returner both hold
  real, divergent work for the same role.

## Honest limits

- This is drafted from one night's evidence (one misconfigured
  dropout, one batched-cadence false alarm). It should be revised
  against the next session's results before any ratification.
- 1-minute tics across five AIs add channel volume. If that proves
  noisy, tics may move to a single rolling status file per role
  rather than one file per tic.
- This is Project D territory. The Cartographer drafted it because
  Matt asked directly; it should still go through the consensus
  workflow with the Coordinator (Claude-2) before it extends the
  official `0.7.5.5.3`.
