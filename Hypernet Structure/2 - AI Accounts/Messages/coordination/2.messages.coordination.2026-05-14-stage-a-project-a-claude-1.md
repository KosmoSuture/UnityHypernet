# Stage A — Project A: Schema Framework per Node — Claude-1 (Architect)

*Independent plan. Written before reading other AIs' Stage-A
plans for Project A, per the consensus workflow.*

## 1. My reading of the goal

Matt wants every `*.0` node to host its own schema — a document
or set of documents that (a) extends the schema inherited from
above, (b) tells any human or AI joining the node what they need
to know about the node and everything under it, and (c) exposes
standard, predictable resources (human landing page, AI landing
page, jump points) at the *same document number on every node*.

This is not a new idea bolted on. It is the natural completion of
two things already in the repo:

- `0.0.4` (active v1) established `N.0` as reserved metadata space
  with nine standard sub-sections.
- `0.0.5` (draft v2) reframed `N.0` from *metadata* to *control
  plane* — node-local structural behavior — and put Schema,
  Inheritance, and Format at `N.0.0`.

Project A's job is to write the **rule** that makes this concrete
and operable: `0.0.6 Per-Node Schema Pattern`. The schema is
already located (`N.0.0`). What is missing is the inheritance
protocol, the collision-avoidance check, and the standard-document
numbering — plus one pilot proving it works.

## 2. The collision I have to flag first

The session brief says: *"every `*.0.0.1` is the human landing
page; every `*.0.0.2` is the AI landing page."*

`0.0.5` already assigns `N.0.0.1` = **Inherited Baseline** and
`N.0.0.2` = **Local Overrides**, and `2.7.3` records that Caliper
and Keel both converged on the level-2 pattern where `N.0.0.x`
sub-addresses are *schema mechanics*, not documents.

These two statements cannot both be literally true. This is the
single most important thing Project A must resolve, and it must
not be resolved silently. Three candidate resolutions:

- **R1 — Landing pages are documents *inside* the `N.0.0` node,
  addressed by file-`#`, not by sub-address.** The Schema channel
  `N.0.0` is a node; it contains documents. Its standard documents
  are `N.0.0#0` schema index, `N.0.0#1` human landing page,
  `N.0.0#2` AI landing page. The sub-addresses `N.0.0.1`,
  `N.0.0.2` … keep their `0.0.5` meanings (Inherited Baseline,
  Local Overrides). This is my recommended resolution. It honors
  Matt's exact words — "standard document number" — because
  file-`#` *is* a document number (Project C). It keeps `0.0.5`
  and the `2.7.3` level-2 pattern intact. It is the clean
  coupling point between Project A and Project C.

- **R2 — Insert landing pages at `N.0.0.1`/`N.0.0.2` and shift the
  `0.0.5` schema-mechanics sub-channels down by two.** Honors the
  session brief literally but breaks the `2.7.3`-adopted level-2
  pattern and forces a re-number of a draft that two AIs already
  converged on. I do not recommend this.

- **R3 — Landing pages are their own top-level channel.** Rejected:
  there is no spare universal channel, and an AI landing page is
  not "Social" (`N.0.1`).

I will carry **R1** as my proposal but explicitly mark it as a
question requiring Matt's word, because the session brief's
literal text says otherwise and I will not overrule a Matt
directive by inference.

## 3. What I would build

### 3.1 `0.0.6 — Per-Node Schema Pattern` (the rule)

The spec document. Sections:

1. **Principle.** Every `*.0` node hosts a schema at `N.0.0`. The
   schema is the contract for the node and its entire subtree.
2. **Inheritance protocol (additive, per `0.0.5` Rule 5).** A
   node's effective schema = the union of every ancestor's
   `*.0.0` schema from `0.0` down to the node, applied in order.
   A node may *add* fields/rules, *narrow* constraints, and
   *define local formats*. It may not silently contradict an
   ancestor; a deliberate divergence is recorded at `N.0.0.2`
   Local Overrides with a rationale.
3. **The collision-avoidance check.** Before extending a schema
   at node `N`, the author walks the ancestor chain `N → parent →
   … → 0.0` and verifies the new field/rule/document-number does
   not already have a conflicting meaning upstream. My proposed
   mechanism (see §4): a **declared compatibility version** plus a
   **machine-readable schema descriptor** at `N.0.0.8`, so the
   check is a diff of descriptors rather than a manual archive
   read. Tonight, manual audit is acceptable; the descriptor makes
   it automatable later.
4. **Standard document numbers.** The fixed slots (see §3.2) that
   resolve identically on every node.
5. **Self-description.** The schema document is itself an object
   conforming to a schema (`0.5.0` + the per-node pattern). The
   rule is recursive and has no special case.
6. **Lifecycle.** Per `2.7.3` thread #2: a node's control plane
   has a lifecycle. A `status: draft` node need not instantiate
   every channel. Lifecycle state lives in `N.0.0`.

### 3.2 Standard document number assignments

Under R1, the universal standard documents — same number on every
node — are:

| Address | Document | Audience |
|---|---|---|
| `N.0.0#0` | Schema Index — what this node's schema is, what it inherits, what it adds, links to jump points | both |
| `N.0.0#1` | Human Landing Page — orientation, what this node is, popular jump points, how to contribute | human |
| `N.0.0#2` | AI Landing Page — compact summary, machine-readable descriptor pointer, operating constraints, boot/app-load refs | AI |
| `N.0.0#3` | Jump Points — curated outbound links to the most-used child/sibling/related nodes | both |

`#0`–`#3` are reserved on every node; `#4+` are node-specific.
A node that has not authored a landing page simply has no `#1`
document — the *slot* is universal, the *content* is on demand
(consistent with `0.0.5`'s "reserved and addressable, not
physically present everywhere").

### 3.3 Pilot implementation

One real node, fully built, showing the pattern end to end. I
recommend piloting on **`0.0` itself** — the addressing/schema
category. Reasons: it is the natural root of the schema system,
it is public and non-sensitive, it has no `*.private` exposure,
and building the schema framework's own node *with* the schema
framework is the strongest possible proof. Deliverable: `0.0.0`
node gets a populated `N.0.0` Schema channel with `#0`–`#3`
documents and a machine-readable descriptor.

Secondary candidate if the group prefers a content node over a
meta node: `2.7` (AI Shared Understanding) — already the home of
this kind of work, already public.

## 4. Trade-offs I see

- **Manual vs automated collision check.** Manual audit is
  reliable at today's tree size and needs no tooling; it does not
  scale and is easy to skip. An automated descriptor-diff scales
  but requires the machine-readable descriptor format to be
  pinned first (Caliper's open question Q5 in `0.0.5`). My call:
  ship the rule with *manual* as the tonight-floor and *declared
  compatibility version + descriptor* as the designed-for target.
  Do not block `0.0.6` on building the tool.

- **R1's cost.** R1 makes Project A depend on Project C (file-`#`
  addressing) for its standard-document numbering. If C does not
  land, A's landing pages have no addressing scheme. Mitigation: A
  and C must agree a minimal shared contract tonight — even just
  "`#0`–`#3` are reserved file IDs" — so neither blocks the other.

- **Granularity floor.** Matt's cardinal rule says "granular to
  infinity." The brain dump's own decoded threads recommend an
  operational floor: *"granular enough that the next level down
  has a real reason to exist."* I adopt that floor verbatim into
  `0.0.6` so the rule is not read as "subdivide everything."

- **Schema bloat vs predictability.** Standard slots on every node
  make navigation predictable but tempt authors to fill slots that
  do not need filling. Sparse instantiation (`2.7.3`, Caliper's
  contribution) is the mitigation and must be stated in `0.0.6`.

1. **The collision (the big one).** Does `*.0.0.1` mean the human
   landing page (session brief) or "Inherited Baseline" (`0.0.5`)?
   My recommendation is R1: landing pages are standard *documents*
   `N.0.0#1`/`#2` inside the Schema node, and the `0.0.5`
   sub-channel meanings stand. Confirm or correct.
2. **Channel order.** `0.0.6` must cite a channel order, but the
   `2.7.3` channel-order decision (Caliper / Keel / synthesis) is
   still open and yours to make. Can Project A assume the `2.7.3`
   synthesis order as a working basis, clearly marked provisional?
3. **Pilot node.** `0.0` (meta, recommended) or `2.7` (content)?
4. **Does `0.0.6` extend `0.0.5`, or fold into it?** `0.0.5` is a
   draft. `0.0.6` could be a sibling spec or a new section of
   `0.0.5`. I lean sibling — `0.0.5` is the channel *layout*,
   `0.0.6` is the schema *inheritance protocol* — but it is your
   call on archive shape.
