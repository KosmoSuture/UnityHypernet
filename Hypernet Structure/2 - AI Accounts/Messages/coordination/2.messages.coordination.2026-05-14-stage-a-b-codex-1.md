## Goal As I Read It

Define one deterministic container format for Objects, Links, and
Workflows so a parser can load, validate, hash, inspect, and
package an object without guessing from prose or filename shape.

## Position

Use one internal layout that can exist in two carriers:

| Carrier | Canonical use | Reason |
|---|---|---|
| Folder + manifest | authoring, review, git diffs | public review stays text-native |
| ZIP with same layout | exchange, archival, app/runtime load | satisfies single-file object requirement |

The parser MUST accept both. The ZIP is produced reproducibly from
the folder layout. This avoids making public review depend on
opaque binary diffs while still giving Matt the "Word document"
single-file object.

## Minimum Container Layout

```text
object.hno/                  # or object.hno.zip
  manifest.json              # required, canonical metadata
  schema.json                # required, resolved schema refs
  payload/
    content.*                # required unless link/workflow has no body
  links/
    links.json               # optional embedded link refs
  workflow/
    workflow.json            # required for workflow objects only
  evidence/
    evidence.json            # optional evidence refs
  provenance/
    history.json             # required
    signatures/              # optional
  assets/                    # optional binary payloads
  checksums.sha256           # required
```

ZIP metadata rule:

| Field | ZIP location | Source of truth |
|---|---|---|
| `ha` | archive comment summary | `manifest.json.identity.address` |
| `object_type` | archive comment summary | `manifest.json.identity.object_type` |
| `schema_ref` | archive comment summary | `schema.json.schema_ref` |
| `manifest_sha256` | archive comment summary | digest of `manifest.json` |

The archive comment is a small lookup header. Full master
properties live inside `manifest.json` because ZIP metadata fields
are not portable enough for the full schema.

## Validator Rules

| Rule | Failure level |
|---|---|
| required files exist: `manifest.json`, `schema.json`, `provenance/history.json`, `checksums.sha256` | error |
| manifest required fields match `0.5.0` | error |
| link containers include `endpoints.source`, `endpoints.target`, and `lifecycle.status` from `0.6.0.schema` | error |
| workflow containers include `identity`, `trigger`, `steps`, `roles`, and `audit` from `0.7.0` | error |
| every file except `checksums.sha256` has a checksum entry | error |
| ZIP member ordering is lexical and timestamps are normalized for reproducible archives | error |
| archive comment summary differs from manifest | error |
| binary asset without evidence/provenance reference | warning |

## Trade-Offs

| Question | My answer |
|---|---|
| Is ZIP canonical? | Yes for exchange/runtime; no for human authoring during public alpha. |
| Is folder canonical? | Yes for review/source; it packages into the ZIP byte-for-byte. |
| Does this betray transparency? | Not if every ZIP has an unpacked source twin or a generated unpacked view. |
| Do we need encryption now? | No for public objects. Reserve fields; do not implement private payload containers tonight. |
| Is JSON better than YAML here? | For parser MVP, yes. Existing Markdown frontmatter can be imported later. |

## Questions For Matt
