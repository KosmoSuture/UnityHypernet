## Residual disagreements / isolated axes

**Axis 1 — Version+fragment ordering**: Codex-2 says `@` before `#` (`0.3@v4#2`); Codex-1 agrees (`HML://0.3@v2#2`); Claude-1 in Stage A says `#` before `@` (`0.3#2@v3`). **Real ordering disagreement**, but only Claude-1 differs and acknowledges the alternative. Recommended: Codex-1/Codex-2 ordering (`@` before `#`), because it reads "version 2 of node 0.3, file 2 within that version" — more natural and matches Codex-1's explicit example with three rendered cases.

**Axis 2 — ID reuse after deletion**: Claude-1 says IDs are NEVER reused (cites `2.0.19` no-permanent-deletion ethos). Codex-1 says "stable unless intentionally renumbered" (allows reuse with migration). Codex-2 asks Matt. **Matt-decision axis.** Recommended default: Claude-1's "never reused" because it aligns with `2.0.19`.

**Axis 3 — Reserved band size and ownership**: Claude-1 proposes `#0`-`#9` reserved (10 slots) as coupling point with Project A. Codex-1/Codex-2 didn't specify band size. **Matt-decision axis** (or Project A/C joint decision).

**Axis 4 — Separator final**: All three AIs recommend `#`; Matt flagged visual preference for `:` in brain dump. **Matt's call.** AIs' position: `#` canonical, `:` allowed as display alias only.

**Axis 5 — File IDs in subdirectories**: Codex-2 asks "should file IDs apply only to root files or also to descendant folders?" Codex-1 didn't address; Claude-1 implicitly assumed node-root files. **Matt-decision axis** OR can be answered at architectural level: `N#k` addresses files in node N's *primary directory*; deeper files use deeper node paths.

**Axis 6 — Visible filename format**: Codex-1 asks "human-small `1` or padded `001`?" Cosmetic; **Matt's preference**.

**Axis 7 — Subsection anchors**: Both Codex AIs say "not tonight." Claude-1 doesn't address. Consensus: defer.
