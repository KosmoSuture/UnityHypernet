## Convergence

All three Project B plans independently chose the same spine:

```text
source/review form: directory package
transport/release form: deterministic zip
source of truth: manifest
zip metadata: mirrored lookup summary only
```

I treat the two-carrier design as converged. A zip-only canonical
format would betray the public-alpha review model; a directory-only
format would miss Matt's single-file object requirement.

## What Changed My Plan

| Source | Change adopted |
|---|---|
| Claude-1 | Make "directory-canonical, zip-transport" the headline and state zip is generated, never hand-authored. |
| Claude-1 | Use `.hno` / `.hno.zip` instead of keeping extension open. |
| Claude-1 | First pilot is a simple document; boot sequence becomes second pilot, not first. |
| Codex-2 | Add mandatory hostile-zip checks: path traversal, symlink, zip bomb, oversized file, unexpected absolute paths. |
| Codex-2 | State that file-level `N#id`, object `ha`, and content hash are separate identities. |

## Revised Format Skeleton

```text
<object>.hno/
  manifest.yaml
  manifest.canonical.json
  schema/
    schema.json
  content/
  links/
    links.yaml
  provenance/
    history.yaml
  evidence/
  signatures/
  assets/
  checksums.sha256
```

Rules:

| Rule | Level |
|---|---|
| `manifest.yaml` is authoritative for humans and repo review. | MUST |
| `manifest.canonical.json` is generated from YAML and used for deterministic parser/hash paths. | MUST |
| `.hno.zip` is generated from `.hno/`; direct hand-editing a zip is unsupported. | MUST |
| Every non-directory member has a checksum entry. | MUST |
| Zip member ordering, timestamps, permissions, compression, and paths are normalized. | MUST |
| Zip metadata mirrors only `ha`, `object_type`, `schema_ref`, and manifest hash. | SHOULD |
| Unpack tooling rejects absolute paths, `..`, symlinks, excessive compression ratio, and oversized entries. | MUST |

## Identity Boundary With Project C

| Identifier | Meaning |
|---|---|
| `ha` | object identity in the Hypernet graph |
| `N#file_id` | locator for a plain file inside a node |
| `integrity.hash` | content equality marker |
| container internal path | member path inside one object package |

A file promoted into an object container leaves the `N#file_id`
namespace through a recorded migration. Container members do not
receive public `N#id` file refs.

## Implementation Basis

I still recommend a small parser/validator module first:

```text
hypernet/container/
  manifest.py
  load.py
  pack.py
  validate.py
```

First fixture: a simple `0.5.3` document package. Second fixture:
a `0.5.17` boot sequence package, because boot-sequence hash
authentication is load-bearing in `0.5.0`.
