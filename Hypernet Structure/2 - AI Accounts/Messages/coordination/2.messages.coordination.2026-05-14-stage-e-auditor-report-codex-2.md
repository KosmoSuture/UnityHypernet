## Blocking Findings

### BLOCKER 1 - Project B duplicate address

Two different files claim `ha: "0.5.0.1"`.

Impact: public readers and future AIs cannot know which Object
Container Format draft is the canonical draft. This directly
violates the address-consistency expectations Project A and Project
C are trying to formalize.

Required before completion:

- choose one canonical path;
- merge any unique content from the non-canonical draft;
- preserve redirect/supersession evidence;
- do not delete either file without Matt approval.

### BLOCKER 2 - Project B wrong cross-reference to File-Level Addressing

The longer Object Container Format draft references file-level
addressing as `0.0.0.1`, but the landed file-level addressing draft
is `0.0.7`.

Impact: cross-project address references are inconsistent.

Required before completion:

- update references to the actual draft address, or explain why
  `0.0.0.1` will be created as a redirect/alias.

### BLOCKER 3 - Project C draft omits the reserved-band decision

`0.0.7 File-Level Addressing.md` defines grammar and allocation
rules, but does not record the `#0`-`#9` reserved standard-document
band that Stage D tied to Project A's R1.

Impact: Project A's preferred R1 cannot be implemented from the
current Project C draft without adding the reserved-band contract.

Required before completion:

- either add reserved-band language to `0.0.7`, or explicitly mark
  the reserved band as pending Matt decision and block Project A R1.
