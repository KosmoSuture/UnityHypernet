## Normative Rule 1: Two-Layer Architecture

Per Codex-2's auditor finding ("Medical imports need two layers: immutable source record + normalized view"):

**Every medical record MUST be stored as TWO addresses:**

```text
1.X.6.1.<category>.<id>          # normalized view — searchable, AI-readable, comparable
1.X.6.1.<category>.<id>.source   # immutable source — original provider format, never edited
```

**Failure modes the two-layer architecture prevents:**
- Lossy normalization claims that originals support but normalized form doesn't (med dose unit mismatches, lab reference range substitution, ICD code revisions over time)
- Disputed transformations (when AI-normalized differs from clinician-validated)
- Audit trail breakage (regulators may demand original artifact)

**The source layer is write-once, append-only.** The normalized layer may be regenerated if transformation logic changes; every regeneration is logged at `1.X.6.<category>.<id>.transform_log`.

## Normative Rule 2: Coding System Required Per Category

| `1.X.6.1.*` Category | Required Coding System | Fallback if not coded |
|---|---|---|
| `.1` Encounters | CPT (procedure) + ICD-10 (problem list) | Raw description with `coding_status: uncoded` flag |
| `.2` Imaging | DICOM (study/series) + RadLex (anatomy/finding) | Raw modality + body part text |
| `.3` Lab Results | LOINC (test) + UCUM (unit) | Test name + unit text |
| `.4` Procedures & Surgeries | CPT or ICD-10-PCS | Procedure name |
| `.5` Diagnoses | ICD-10 (problem) + SNOMED CT (problem and refinement) | ICD-10 only acceptable; raw text triggers `coding_status: uncoded` |
| `.6` Medications | RxNorm (drug) + UCUM (dose unit) | Brand+generic name + dose text |
| `.7` Allergies | RxNorm or UNII (allergen) + SNOMED CT (severity) | Allergen name + severity text |
| `.8` Vaccinations | CVX (vaccine) + MVX (manufacturer) | Vaccine name + manufacturer text |
| `.9` Mental Health | ICD-10 + DSM-5 | ICD-10 only acceptable |

**Uncoded records are valid for import but flagged in the schema for later coding pass.** Validators emit `coding_status: uncoded` warnings (not errors); a "coding completeness" health metric tracks coverage.

This implements Codex-2's "every normalized item needs source, timestamp, units, coding system, confidence, and transformation provenance."

## Normative Rule 4: Five-Tier Consent Model

Per Codex-2's "consent tiers: emergency, clinical, research, AI-assistant, public-summary scopes":

| Tier | Default visibility | What can read | What can write | Use case |
|---|---|---|---|---|
| **Public summary** | public | Anyone (with mandala if private) | Account owner only | Public health profile (allergies, blood type) for emergency strangers if user opts in |
| **AI-assistant** | private | Account owner's embassy AIs + designated AI specialists | Account owner | Routine AI-medical help (refill reminders, drug interaction checks, appointment prep) |
| **Clinical** | private + extra-scrutiny | Account owner, embassy AIs with clinical scope, named providers | Account owner, named providers, embassy AI with clinical scope | Provider-to-account exchange (lab results, encounter notes) |
| **Research** | private + extra-scrutiny + mandala-gated | Granted researchers per F4 mandala | (read-only) | Research grants (F4 scope) |
| **Emergency** | private + extra-scrutiny + time-bound | Authorized emergency responders during active episode (per F5) | (read-only for responders, append-log for episode AI) | Emergency break-glass (F5 scope) |

Each record carries `consent_tier_required` field. Read attempts at insufficient tier produce audit events.

## Schema for `1.X.6.1` Clinical Records (refining Keel's 1.0.4 buildout)

```yaml
clinical_record:
  ha: "1.X.6.1.<category>.<id>"
  object_type: "clinical_record"
  visibility: "private"
  consent_tier_required: "clinical"
  category: "encounter|imaging|lab|procedure|diagnosis|medication|allergy|vaccination|mental_health"
  
  # Two-layer architecture
  source_ref: "1.X.6.1.<category>.<id>.source"
  normalized_at: "ISO timestamp"
  transformation_log_ref: "1.X.6.1.<category>.<id>.transform_log"
  
  # Coding
  coding:
    primary_system: "ICD-10|CPT|LOINC|RxNorm|DICOM|..."
    primary_code: ""
    secondary: []
    coding_status: "coded|uncoded|partial"
    coded_by: "ai|provider|user|imported"
    coded_at: "ISO timestamp"
  
  # Temporal
  event_date: "ISO date"
  recorded_date: "ISO date"
  
  # Provenance
  source_system: ""
  source_provider_ref: "1.X.6.4.<provider-id>"
  source_received_at: "ISO timestamp"
  
  # Mandala/sharing
  mandala_scope: []
  shared_with_providers: []
  
  # Confidence
  confidence: "high|medium|low|unverified"
  
  # Category-specific payload
  payload: {}
```

**Category-specific payloads** (`.payload` field above) carry the dimension-specific data:

- `.payload` for `encounter`: provider_ref, location_ref, encounter_type, chief_complaint, hpi, ros, exam, assessment, plan, follow_up
- `.payload` for `imaging`: modality, body_part, procedure_code, indication, findings_text, impression_text, dicom_study_ref
- `.payload` for `lab`: test_loinc, result_value, result_unit_ucum, reference_range, flag (high/low/critical/normal), specimen, ordering_provider_ref
- `.payload` for `medication`: drug_rxnorm, brand, generic, dose, dose_unit_ucum, frequency, route, start_date, end_date, prescriber_ref, refill_history
- ...and so on per category

## Family Medical History

Schema slot: `1.X.6.7 Family Medical History`

```yaml
family_condition:
  ha: "1.X.6.7.<id>"
  relation_ref: "1.X.7.1.<family-member>"
  condition_name: ""
  age_of_onset: 0
  status_at_recording: "active|resolved|deceased"
  hereditary_suspected: false
  recorded_by: "user|provider|imported"
```

**Privacy consideration**: family medical history is ALSO data about another person. The relation is the family member, who has their own `1.X` if a Hypernet citizen. Default: the family condition record stores summary at the account owner's `1.X.6.7`, with full record (if any) at the family member's `1.X.6` (mandala-gated to the account owner).

## Validators (F2-level rules)

| Rule | Failure |
|---|---|
| Every clinical record has `source_ref` to immutable source | error |
| Every clinical record has `consent_tier_required` field | error |
| `coding_status: uncoded` records are accepted but flagged in completeness metric | warning |
| Mental health records default to `consent_tier_required: clinical+` | error if lower |
| Substance use records default to `consent_tier_required: clinical+` with `42_cfr_part_2_flag` | error if missing |
| Pediatric/guardian medical records have `guardianship` block populated | error |
| Family medical history records cross-link to `1.X.7.1` family member if a Hypernet citizen | warning if absent |
