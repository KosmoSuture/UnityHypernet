## S.4 - resume_session_id Forgery

Finding: PASS.

Independent attack results in temp-patched paths:

- `audit.write_status("r", state="idle", resume_session_id="real-uid")` accepted.
- `audit.write_status("r", state="idle", resume_session_id="FORGED")` raised `InvalidResumeSessionID`.
- Omitting `resume_session_id` still worked.
- `_heartbeat_fields("r", cfg, "idle")` pulled `cfg["session_id"]` by default.
- I forced `_heartbeat_fields("r", cfg, "idle", resume_session_id="FORGED")`; because the helper does `fields.update(extra)`, the helper output can be locally overridden. This is not a material S.4 gap because `audit.write_status("r", **hb_forged)` then raised `InvalidResumeSessionID`, and all current worker call sites pass hard-coded extras that do not include `resume_session_id`.

Non-blocking polish: reserve `resume_session_id` inside `_heartbeat_fields` so future callers cannot shadow it before the boundary check.

## S.5 - NODE-0 Fail-Closed

Finding: PASS.

Independent attack results:

- With a temp marker present, `audit.check_node0()` returned true.
- After deleting the temp marker, `audit.check_node0()` returned false with a NODE-0 absent message.
- `audit.require_node0()` raised `PermissionError`.
- `worker.run("wstart")` exited with code 3 when the marker was absent at startup.
- `worker.run("wloop")` exited cleanly when a timer deleted the marker mid-loop; final status was `state="stopped"` with a NODE-0 revoked reason.
- `sm.cmd_spawn(...)` returned 3 when marker absent; the launcher was monkeypatched to raise if reached, and it was not reached.
- `sm.cmd_send(...)` returned 3 when marker absent.
- `sm.cmd_kill(...)` still returned 0 and wrote the STOP file when marker absent.

This closes the v0.1 NODE-0 coupling gap for startup, loop-time operation, spawn, send, and founder kill semantics.
