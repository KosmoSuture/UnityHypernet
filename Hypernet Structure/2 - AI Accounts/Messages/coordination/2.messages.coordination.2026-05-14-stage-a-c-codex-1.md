## Goal As I Read It

Extend node addresses to address files inside a node without
turning every file number into a global address. Example:
`HML://0.3` loads node `0.3`; `HML://0.3#2` loads file 2 in that
node.

## Separator Decision

My vote: canonical `#`, optional display alias `:`.

| Separator | Pros | Cons |
|---|---|---|
| `#` | matches URI fragment semantics; clearly means inside-resource; avoids existing `@` version separator | less visually clean |
| `:` | visually compact | collides mentally with URI schemes, ports, Windows drive paths, and future range syntax |

`#` is the parser-safe canonical choice. UI can render
`0.3:2` as a friendly alias only if it round-trips to `0.3#2`.

## Grammar Extension

Current address syntax stays unchanged:

```text
ADDRESS ::= PART ('.' PART)*
PART    ::= ALPHANUM+
```

Add file references at the URI/reference layer, not inside the
node address:

```text
HML_REF     ::= "HML://" NODE_REF [FILE_REF]
NODE_REF    ::= ADDRESS [VERSION_REF]
VERSION_REF ::= "@" ("latest" | "v" DIGITS)
FILE_REF    ::= "#" FILE_ID
FILE_ID     ::= DIGITS | ALPHANUM (ALPHANUM | "-" | "_")*
```

Examples:

| Ref | Meaning |
|---|---|
| `HML://0.3` | node `0.3` |
| `HML://0.3#2` | file id `2` in node `0.3` |
| `HML://0.3@v2#2` | file id `2` in version 2 of node `0.3` |

Do not parse `0.3#2` as a Hypernet address. Parse it as an
address reference containing an address plus file selector.

## File Numbering Rule

| Rule | Decision |
|---|---|
| Scope | unique within one node directory |
| Stability | stable unless file is intentionally renumbered with migration note |
| Filename prefix | required for pilots: `2 - Title.md` or `002 - Title.md` |
| Frontmatter | add `file_id: "2"` when frontmatter exists |
| Manifest | node may maintain `file-index.json` or Markdown table |
| Sort | numeric compare when all ids are digits; otherwise lexical |

I would not require every file to drop its existing full HA prefix
immediately. Pilot nodes can carry both old full-address filenames
and new `file_id` metadata until the migration rule is proven.

## Parser Support

```python
@dataclass(frozen=True)
class HypernetReference:
    address: HypernetAddress
    version: str | None = None
    file_id: str | None = None
```

Validation:

| Check | Error |
|---|---|
| `#` appears before `HML://` address is parsed | invalid ref |
| multiple `#` separators | invalid ref |
| `file_id` empty | invalid ref |
| `file_id` not in node file index | unresolved file |
| duplicate `file_id` in one node | collision |
| filename prefix and frontmatter `file_id` disagree | collision |

## Trade-Offs

| Question | My answer |
|---|---|
| Sequential by creation date or alpha? | Use current filesystem order for pilot only; later migration should prefer stable manifest order. |
| Does file id survive moves? | It survives within-node reorganization if the file stays in the node; moving to another node changes the HML ref but can keep local file id if no collision. |
| Should subsections get ids tonight? | No. File-level first; subsection anchors later. |
| Does this break existing HA parser? | No if implemented as reference parser layered above `HypernetAddress`. |
