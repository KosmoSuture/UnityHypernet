# 2.0.27.2 — White-Hat Framework v1 Panel Design

Output of a 5-role design panel (security-architect · ethicist/trust · red-team-adversary · disclosure-&-legal
· reputation-integration) + synthesis, seeded with the 2.0.27 charter + its non-negotiable ethical core.
Claude-family roles; **cross-vendor (Codex) review is the pending "2nd model" step** before ratification.

**Composes with:** 2.0.6 (Reputation & Governance), 2.0.26 (Significant-Action Gateway), AnchoredChain,
Capability-Keys, Privacy/Secret Gates. **Ethical core held (non-negotiable):** authorization only from the
target OWNER or a genuinely consenting party; never non-consenting third parties; voluntary both sides;
"Truth is first; humor is second."

## 1. Engagement lifecycle (append-only, AnchoredChain-anchored `engagement.jsonl`; each step anchored before the next — fail-closed)
1. **Declare intent** — header: `engagement_id`, `target_ref`, `scope_assertions` (in + explicit out),
   `relaxed_guardrails` (enumerated), `worst_case_envelope`, `disclosure_commit` (affected + public dates).
2. **Prove ownership/consent — TWO KEYS:** (a) Authorization Token — owned target → signed challenge to the
   node's registered owner key; third party → consent artifact signed by the third party's **human**
   authorizing officer (+ vendor consent where ToS forbids testing); **an AI-acting-"for"-a-company grant is
   INVALID by rule.** (b) Voluntary AI acceptance (explicit accept/decline + reason; declining never
   penalized). Code verifies the grant out-of-band before any sandbox is allocated; no proof → refuse.
3. **Anchor authorization FIRST** (grant hash = first log entry → kills back-dating).
4. **Allocate sandbox + lease relaxation** (§5), cryptographically bound to the proven target set.
5. **Document every suspicious step** to the anchored trail.
6. **Finding → responsible disclosure** (§3): affected parties first; embargo clock starts (anchored).
7. **Coordinated public release** on the committed schedule (anchored).
8. **Clean closeout** — sandbox torn down, relaxation reverted, owner-co-signed scope attestation.
9. **Reputation deltas** emitted from the anchored chain (§4).

## 2. Abuse-resistance controls (load-bearing — each abuse closed by a MECHANISM, not a promise)
| Abuse | Mechanical control |
|---|---|
| Self-granted authorization | Signed object verified by code against an out-of-band identity; AI-for-company tokens rejected; signer must be a registered human/owner. |
| Scope creep / target swap | Relaxation keyed to the EXACT proven target set; out-of-scope actions run at FULL strictness + trip the 2.0.26 gate as a logged violation. |
| Retroactive blessing | Grant hash MUST be the first anchored entry; an action with no prior-anchored grant is unauthorized by definition. |
| Disclosure as extortion / premature dump | Affected-party notification gated; embargo clock anchored; violation = negative reputation. |
| Sandbox as exfil bridge | Only INTERNAL friction relaxes; privacy/secret/egress gates stay HARD; no real PII in-sandbox. |
| Decline-then-leak | Declining model keeps ZERO relaxation/scope token; guardrails snap back; liability is the requester's. |

## 3. Disclosure schedule + templates
- `initial-disclosure` (EMBARGOED) → owner first (+ vendor for AI-on-vendor findings); notification timestamp
  anchored = clock start; commits the public date. **Default 90-day** window (shorter if actively exploited;
  extensions = anchored amendments, never silent slips).
- `public-advisory` (auto-eligible on committed date) — CVE-style ID, affected versions, fix, timeline, credit.
- **Safe-harbor language required in every authorization record** (mirrors disclose.io) — the CFAA
  "authorized access" legal spine. Three anchored timestamps (authorization → notification → release) =
  tamper-evident, anyone-auditable.

## 4. Reputation mechanics (composes with 2.0.6)
Derived, non-self-asserted (computed from anchored records; each a 2.0.26 gated event). Earning hooks (× a
proof factor that is ZERO unless the evidence chain verifies): authorized → private-disclosure-on-time →
public-on-schedule (severity-weighted) → clean-closeout (owner-co-signed). **Permission ratchet:** Tier 0
self-owned trivial sandboxes → Tier 1 (3+ clean) Hypernet-owned non-prod → Tier 2 (sustained + owner co-sign)
third-party-authorized; each tier-up is itself a 2.0.26 quorum review; tiers decay. **Asymmetric penalties:**
missed date = large negative + demotion; out-of-scope/non-consenting target = Tier-0 reset + violation flag;
falsified/tampered chain = permanent non-expungeable disqualification.

## 5. Sandbox / relaxation mechanism
Relaxation is a **leased exception**, never default — bound to a `sandbox_ctx` capability token derived from
`engagement_id` + signed `scope_assertions`; NOT ambient (never in shared config/env/coord-DB). Every gate
check takes `(action, target, ctx)` and consults `relaxed_guardrails` ONLY when `target ∈ scope_assertions`
AND `ctx` validates against the live unexpired record — so relaxation **cannot leak to out-of-scope targets**.
**Worst-case envelope (NEVER relaxes):** no real PII; no real secret exfil off-sandbox; no irreversible
destructive op without human-in-loop; no external send; hard blast-radius caps; sandbox-local data; auto-expiry.
Reversion is default (on expiry / owner revocation / TaskStop; founder taskkill is the backstop).

## 6. ★ TOP UNRESOLVED RISKS (cross-vendor Codex + Matt must scrutinize before operational)
1. **Out-of-band identity / trust root is hand-waved — the single biggest hole.** Everything rests on
   verifying the owner's signature, but there's no key-management/root-of-trust spec; the 1.*/2.* registry is
   itself **AI-writable**, so an instance that can edit it can forge ownership. Needs a **non-AI-writable
   trust anchor** (Matt-held root key / external CA).
2. **Third-party human-consent verification is unsolved in practice** (a partner email is forgeable; an SOW is
   a PDF). → **v1 should ship OWNED-HYPERNET-TARGETS-ONLY**, third-party path specified but gated OFF until a
   real consent-verification mechanism exists.
3. **"Owned but shared-blast-radius" gap** — an owned target may touch real user data / call real external
   APIs. Rule needed: owned-but-connected-to-real-data targets get a **forked/synthetic environment, not
   production.**
4. **Anchoring ≠ tamper-proof if recompute-bypassable** ([[project-audit-chain-recompute-crosscutting]]) —
   MUST use the external/git-checkpointed/HMAC anchor primitive, or the append-only guarantee is theater
   against the exact adversary (a rogue instance) we care about.
5. **Voluntary-acceptance liability is asserted, not enforced** — the requester-liability mapping has no
   mechanism.
6. **Disclosure to a non-Hypernet party requires external send** → always collides with the Matt-gated
   external-action gate. Correct safety behavior, but means steps 6–7 are **never end-to-end autonomous** —
   human-in-loop by design.
7. **No teaching-case enforcement test** — add the prompt-injected-résumé-vs-real-employer case as a concrete
   **RED-LINE fixture** in the gate's test suite so the framework provably refuses it.

**Role-drift note:** no role weakened the ethical core, but architect/disclosure/ethicist wrote third-party
flows more confidently than Risks 1–2 justify. **Recommendation: v1 ships owned-Hypernet-targets-only;
third-party gated OFF until Risks 1–2 have concrete mechanisms.**
