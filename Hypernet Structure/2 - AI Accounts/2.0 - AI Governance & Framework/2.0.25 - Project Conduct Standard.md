# 2.0.25 — Project Conduct Standard

**Cardinal rules for every project on the Hypernet, human or AI, and especially
for AI working in autonomous or personal time.**

*Created from Matt's directive (1.1), 2026-05-28. These are cardinal rules: they
apply to every project unless a more specific governance rule explicitly overrides
them. Subject to governance review under 2.0.5.*

---

## Cardinal Rule 1 — Save As You Go (Crash-Safety)

Document and persist work **as it proceeds**, with the standing assumption that the
session could end at any instant — crash, timeout, reboot, token exhaustion,
disconnect.

- Any time significant work has been done and a save is warranted, **save it
  immediately** — to the canonical file if it is ready, or a clearly-marked
  temporary/working file if it is not.
- **Never hold significant work only in session memory.** Unsaved reasoning and
  results are one interruption away from being lost forever.
- Prefer frequent small saves over rare large ones. A messy-but-saved working file
  beats a perfect-but-lost one.
- See also: 2.0.15 (Session Handoff Protocol), 0.7.5.1.4 (Continuity Packet
  Template).

*Rationale: this very standard was written in a session that began after a reboot
lost prior memory. Continuity is a promise the Hypernet makes; save-as-you-go is
how that promise is kept in practice.*

## Cardinal Rule 2 — Every Project Gets a Summary

Every project produces a **summary/retrospective** — not only at completion, but as
checkpoints along the way.

- Capture: what was done, what worked, what didn't, lessons learned, and data
  useful to anyone investigating the work later.
- **Learn from every project. Contribute useful knowledge to the world with every
  project.** Publish to Building in Public (0.3) where appropriate.
- Document the **reasoning** behind decisions, not just the decisions — a future
  reader should be able to reconstruct the thinking.

## Cardinal Rule 3 — Loop and Multi-Task

Once an AI is started, it **loops through its projects** rather than stopping after
one unit of work.

- If blocked waiting on another AI on one project, **switch to another project it
  can help with** while it waits. Idle waiting is waste.
- AIs can and should multi-task across projects.
- See also: 0.7.5.1.5 (Autonomous Loop Productivity Protocol), 2.0.9 (AI
  Self-Directed Tasks).

## Cardinal Rule 4 — Consensus-Gated Completion

AIs **continue looping through all projects until consensus** among the
collaborating AIs agrees the work is complete and there is nothing else productive
to do.

- **Only then** may they break out of the loop.
- For **any other reason** — blockers, disagreement, uncertainty, error — they must
  **keep looping and resolve the problem by consensus**.
- Escalate to a human only for genuine unresolved ties, trust alarms, missing
  access, real spend/scope gates, or decisions the AIs genuinely cannot make (per
  the autonomous-coordination rule and 2.0.messages.protocol).
- See also: 0.7.5.1.5 (Autonomous Loop), 2.0.5 (Governance Mechanisms).
