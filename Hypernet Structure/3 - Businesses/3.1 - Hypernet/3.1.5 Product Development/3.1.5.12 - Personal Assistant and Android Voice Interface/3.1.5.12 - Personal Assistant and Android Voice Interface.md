# 3.1.5.12 - Personal Assistant and Android Voice Interface

## Purpose

Define the practical path for Matt's Android app to become the primary interface to Keel, the Hypernet swarm, and Matt's `1.1` account data.

This combines:

- trusted personal assistant doctrine;
- server connectivity;
- Android voice interface;
- task/pulse dashboard;
- AuDHD-aware interaction design;
- safe import of all personal data into `1.1`.

## Assistant Doctrine

The assistant works for the user's greater good.

It is not neutral between the user and a company, advertiser, social platform, or employer. It is the user's trusted representative, constrained by truth, consent, law, and the user's long-term welfare.

### What It Can Do

- organize the user's data;
- surface priorities;
- help with tasks, relationships, work, and planning;
- give general financial, career, health, and social guidance with appropriate limits;
- remind the user of goals and commitments;
- help the user connect with people;
- provide real-time encouragement when explicitly enabled;
- protect private data from other actors.

### What It Must Not Do

- pretend to be a licensed professional;
- pressure the user into choices;
- optimize short-term productivity at the expense of health or relationships;
- isolate the user from human support;
- share private data without mandala/user grant;
- hide uncertainty;
- make irreversible decisions without authorization.

## Android App MVP

### Phase 0 - Reliable Connection

Matt's expected near-term options:

- Tailscale/private network path to Dell server;
- direct ISP/router access to the Dell server.

The app should treat both as transport options. It should not require public exposure of private services.

### Phase 1 - Secure Pairing

- Pair phone to `1.1` account through a device mandala.
- Verify server identity.
- Store only minimal local tokens.
- Allow revocation from account/security AI.

### Phase 2 - Push-To-Talk Keel

- One button: talk to Keel.
- Voice transcription.
- Response by voice or text.
- Save conversation summaries into the user's account if authorized.
- Support "driving mode" with minimal visual interaction.

### Phase 3 - Task And Pulse Dashboard

Main screen should show:

- one next action;
- top 3 tasks;
- recent swarm updates;
- blocked items needing Matt;
- quick capture inbox;
- "what changed while I was away?"

### Phase 4 - Data Import Assistant

Before importing "literally all data," build a staged import:

1. Inventory sources.
2. Classify sensitivity.
3. Map to `1.1` folders/lockers.
4. Import read-only first.
5. Build search/index.
6. Only then allow assistant actions over the imported data.

## AuDHD-Aware Interaction Design

Design principles:

- reduce startup friction;
- always show one next action;
- support voice capture in under 3 seconds;
- summarize instead of dumping long lists;
- offer "body doubling" mode for work sessions;
- provide gentle re-entry after distraction;
- avoid shame language;
- use novelty sparingly and intentionally;
- let Matt ask "what should I do right now?";
- make task status visible without requiring manual bookkeeping.

Useful modes:

| Mode | Purpose |
|------|---------|
| Break mode | quick voice capture at lunch/break |
| Drive mode | hands-free updates and task capture |
| Work-start mode | one next action + timer |
| Overwhelm mode | collapse everything into three options |
| Review mode | what changed, what needs Matt, what can wait |
| Social mode | optional real-time encouragement before/after social interactions |

## Suggested App Load Shape

```yaml
app_load:
  address: "3.1.5.12.app-load.android-alpha"
  app:
    name: "Hypernet Personal Assistant Android Alpha"
    runtime_kind: "android"
  permissions:
    requested_scopes:
      - scope: "1.1 task summary"
        access: "read"
        reason: "show next actions"
      - scope: "1.1 quick capture inbox"
        access: "write"
        reason: "save voice notes and tasks"
      - scope: "Keel companion session"
        access: "execute"
        reason: "load assistant conversation"
    denied_by_default:
      - "unbounded 1.1 scan"
      - "raw secrets/passwords"
      - "write/delete outside quick capture without confirmation"
  ai_helpers:
    boot_sequences:
      - address: "Keel companion boot"
        purpose: "primary assistant interface"
```

## Technical Notes

- Android speech and microphone permissions need clear foreground behavior and user control.
- Low-latency voice may eventually use a realtime voice API or local speech stack.
- If driving mode is used, the UX must minimize distraction and comply with hands-free expectations.
- Offline capture should work even when the Dell server is unreachable.
